# 归档验收台：本地使用与交接

## 交付结果

本独立产品目录包含完整本机入口。使用者在浏览器选取同一作业的出发基线、现场副本、回传主库及附件，执行只读验收，定位尚未到达的变更和不完整证据，导出中文交接报告。工程数据不会被本工具同步或覆盖。

## 本机启动

需要 Python 3.10 或更新版本和现代浏览器，建议 Chrome 或 Edge。无需账号、联网服务、额外 Python 包或付费工具。

```sh
python server.py --port 8765
```

在本产品目录运行；macOS/Linux 可将 `python` 换成 `python3`。打开 `http://127.0.0.1:8765`；若端口占用，换成 `--port 8766` 并打开对应地址。服务仅监听本机 `127.0.0.1`，不会部署到互联网。在终端按 `Ctrl+C` 停止。直接双击 HTML 只能看到页面，执行数据库验收需要这个本地服务。

## 第一次体验

页面提供构造数据库和文字附件的合成示例。载入后执行验收，查看变更、证据和结果；模拟缺附件后重新验收，查看恢复建议，再载入完整示例恢复。示例只验证软件流程，不代表真实使用者、自然发生故障或现场成果。

也可在产品目录生成可实际选择上传的文件：

产品已附带示例配置及文字附件；SQLite 副本在自己的目录生成，执行：

```sh
python examples/create_demo.py .auto-company/example-inputs
```

生成目录包含三份 `.sqlite`、现场与目标附件根目录、`验收配置.json`。在页面逐一选取三份数据库，分别选取两个附件根目录，将配置中的表、关联、附件列填入高级配置并确认完整声明后验收。所有示例均是合成数据。

## 准备真实工程输入

1. 先备份原始工程；在 QGIS、QField 或既有同步工具完成应有的同步操作。本工具用于验收同步结果。
2. 关闭正在写入数据库的程序，再复制三份数据库。SQLite 使用 WAL 时先通过原工具检查点或可靠备份取得完整副本；不要只复制一个仍在写入的主文件而遗漏 WAL。
3. **出发基线**是离线采集前分发的版本；**现场副本**是设备采集后保存的版本；**回传主库**是本次要确认结果到达的指定办公室版本。三者必须对应同一作业、表结构和稳定主键。
4. 选取 SQLite 或 GeoPackage 数据库文件。导出的 CSV、项目配置文件、损坏数据库、加密库不能替代数据库副本。
5. 准备现场和目标的附件目录，目录下相对路径应与数据库字段一致。例如字段为 `photos/obs-002.txt`，选取的目录根下面应有 `photos/obs-002.txt`。附件名称一致还需内容一致。
6. 填写作业名，按工程需要配置表、关联及附件字段。确认现场副本、附件与本次作业范围齐全后，才勾选证据完整声明。声明由操作者负责，本工具无法独立验证所有设备是否交齐。

多设备请分别保留各设备基线与现场副本并逐个验收，保存报告。当前工具不自动汇总所有设备或推断缺少的设备，也不合并冲突。

## 配置

高级配置是 JSON 对象；填写自己的真实表名和字段名。下面是合成巡检工程的示例，不应照抄到无关工程：

```json
{
  "tables": [
    {"name": "sites", "key": ["uid"]},
    {"name": "inspections", "key": ["uid"]}
  ],
  "relations": [
    {"table": "inspections", "column": "site_uid", "parent_table": "sites", "parent_column": "uid"}
  ],
  "attachment_columns": [
    {"table": "inspections", "column": "photo"}
  ]
}
```

`tables` 指定验收范围，`key` 是稳定且唯一的主键字段数组，支持复合键；键值变化按旧记录删除、新记录新增处理。留空表清单时尝试发现用户表和原生主键。GeoPackage 系统表不作为采集记录验收。遗漏其他业务表会在报告列明并保持未确认，避免把局部结果称为整个返回包完整。无稳定唯一主键或不兼容模式时保留未确认，不以行号猜测记录对应关系。

`relations` 表示子表字段应引用父表字段，用于补充数据库未声明的业务关联。`attachment_columns` 指定包含附件相对路径的字段。空附件列清单表示操作者明确声明所选范围没有附件引用，仍需证据完整声明；不要为获得绿色结果隐去真实附件字段。附件字段一格只支持一个相对路径，不支持 URI、列表、跨根目录链接或远程下载。

记录键、字段值和显式 `relations` 按 SQLite 实际存储类型与值一起核对：整数、实数和文本分别处理。显式关联的父子标识需使用一致存储类型；如果原工程将整数标识存为文本，先核对业务约定并在原工具中统一类型后重验。

## 读取结果与恢复

| 结果 | 含义 | 下一步 |
|---|---|---|
| 通过 | 当前声明范围内，有证据支持预期变更和必需附件已到达 | 核对作业范围、来源与目标，保存报告和输入副本 |
| 需复核 | 发现字段、记录、关联、结构或附件内容等明确问题 | 按表、键、字段或路径定位；在原工程/同步工具中修正后保存新副本重验 |
| 附件延后 | 数据符合要求，按明确延迟策略仍有附件未到达 | 保留待补清单；补齐附件后重新验收，不称完整交付 |
| 未确认 | 缺少源证据、完整声明、可靠主键或其他必要信息 | 补齐所列证据或兼容输入再验收，不能据此断言全部完成或数据丢失 |

明确问题优先显示为需复核；报告同时保留证据不足事项。办公室对现场未修改字段的合法变更可保留；同一字段不同值会要求复核。现场删除的记录仍存在于主库也会报错；不自动删库或决定冲突胜方。新记录需要目标整行匹配，包含几何原始字节。

附件策略“必需”要求本次引用附件完整到达；“允许延迟”仅对目标缺失附件给出附件延后。同名附件内容不同仍然是需复核，现场缺附件源证据仍不能确认。修改任何输入或配置后原结果失效，应重新验收；输入错误可以修正后重试，不需要重新启动服务。

## 报告与隐私

支持 JSON（结构化证据）、CSV（问题清单）和独立 HTML（可离线打开的完整阅读报告）导出。报告保留作业、输入 SHA-256、策略、变更、问题及限制。交接时保存报告、原始输入副本与配置；报告哈希证明字节来源对应，不证明设备或操作者身份。

数据库整数（包括记录键、字段值和关联定位）完整保留 SQLite 正负 64 位范围，不经浏览器数字转换。页面、CSV 和独立 HTML 的单字段值以“整数 · 精确十进制值”标明类型，记录键保留含类型标签的 JSON；JSON 中整数表示为 `{"type":"integer","value":"9007199254740993"}`，其中 `value` 是精确十进制字符串。普通文本仍为 JSON 字符串，因此整数 `9007199254740993` 与文本 `"9007199254740993"` 是不同身份。处理 JSON 的下游程序应按该类型标记读取，不要将 `value` 转成 JavaScript `Number`；需要计算时使用支持精确整数的类型。报告中的条数、文件字节数等受限元数据仍为普通 JSON 数字。

数据库和附件通过浏览器发送至本机 Python 进程；不上传云端。数据库临时副本只在验收期间保留，结束后清理；报告包含实际字段值和附件路径，应按工程敏感资料管理。页面不自动持久化输入，刷新或关闭后需重新选择；下载报告由浏览器保存，使用者自行管理和删除。停止服务可结束本机访问。

## 已知边界

- 上传的三份数据库与两组附件原始内容合计最多 100 MiB；三个库所读记录合计最多 100,000 条，最多 50 张业务表、每表 200 个字段。超限会提示分批或缩小工程范围，不能声称已验收超限部分。
- 只验收所选表、可读普通 SQLite/GeoPackage 结构与明确附件引用，不读取项目样式、表单配置或原厂同步日志。
- 几何和其他 BLOB 以原始字节核对，不进行坐标系变换、拓扑验证、空间等价或现场真实性判断。需要 SQLite 空间扩展的特殊约束和编码可能需要原厂工具处理。
- 所选表的列、建表语句、索引和触发器定义要求三份副本一致；仅格式差异也可能保守地返回未确认。GeoPackage 的几何字段元数据和引用坐标系定义也须一致，更新时间或包络范围变化不当作采集记录冲突。
- 不处理文件仍在写入、加密数据库、缺 WAL 的不完整副本、无稳定主键、复杂模式迁移或远程附件。
- 所有材料和报告是本地软件验收证据；未实测完整 QGIS/QField/Mergin 移动客户端或真实设备，不宣称替代其同步能力。
- 既有 GeoDiff、SQLite 和文件哈希能覆盖主要故障，本产品将它们对应的核对流程集中呈现；创新优势、真实采用、购买与利润仍未验证。

## 开发验证

本目录运行 `python -m unittest discover -s tests -v`，覆盖数据库、HTTP 和真实浏览器上传/导出。浏览器部分需要 Node.js、`npm ci` 安装的 Playwright 开发依赖以及 `npx playwright install chromium` 安装的测试浏览器；也可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已有 Chrome/Chromium。日常验收只需要 Python 和浏览器。

检查使用独立构造的普通 SQLite 与 GeoPackage 几何字节证据、本机 HTTP、真实 Chromium 文件与目录选择。自动化产物保存到 `.auto-company/browser-evidence/`；独立展示副本不附带原运行私有登记或模型日志。

本副本已在 Windows 原生 Python 与 Chrome 验证；这不构成真实移动设备、QGIS/QField/Mergin 客户端或现场真实性验收。
