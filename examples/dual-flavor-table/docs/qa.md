# 一桌双味质量检查

测试对象是本地浏览器产品；合成输入与自动化操作不代表真人使用、实际烹饪或商业验证。

| 风险 | 自动检查重点 | 仍需现实验证 |
| --- | --- | --- |
| 份数与采购量错误 | A/B 各 1–4 份、合计不超过 6，采购总量与分盘量一致 | 家庭实际食量差异 |
| 筛选表面生效、食材仍混入 | 素菜、时间、实际采购食材排除，包含口味调味料 | 过敏及医学饮食要求不在产品保证范围 |
| 两种口味无法独立执行 | 共享备料、分盘量、A/B 单独调味、完整主食/蛋白/蔬菜 | 炉灶差异、实际口味与烹饪时间 |
| 进度误丢失 | 采购/烹饪勾选重载恢复；重新生成的取消与确认 | 浏览器主动清除站点数据 |
| 损坏数据造成白屏 | 无效本地存储与 JSON 导入给出恢复入口，完整备份恢复；外来应用、无效步骤、重复标识、超过 100 KB 的文件拒绝覆盖 | 不同设备的数据迁移 |
| 本地保存被浏览器拒绝 | 合成 `QuotaExceededError` 验证明确提示，当前勾选可继续并下载完整备份 | 不同浏览器的实际存储策略 |
| 导出不可用 | 实际文本和 JSON 下载读取、打印入口调用 | 实体打印机的排版与输出 |
| 手机上难操作 | 小屏宽度、键盘生成、焦点与可访问名称 | 屏幕阅读器与触屏长期使用 |

`tests/engine.test.js` 使用 Node 原生 `node:test` 验证核心结果与非法输入。`tests/browser.test.js` 使用 Playwright 与 `node:test` 验证完整任务；服务器仅绑定 `127.0.0.1`、使用临时端口，并在测试结束时清理服务器和浏览器。

运行入口：产品目录执行 `npm test`。浏览器依赖可来自产品 `node_modules` 或框架已有 `scripts/media/node_modules`；缺少依赖时应明确失败，不能将跳过写成通过。

## 正式证据与环境恢复

首轮历史：共有8项引擎与7项浏览器检查，两个文件的语法检查通过。本轮新增回归的功能状态以正式运行器的最新结果为准，不用静态文档代替回执。历史失败与最新检查均保存在程序证据中，周期结论见框架 `docs/delivery/RESULT.md`。

静态协作处理了完整配置与 `findMenus` 的接口冲突、相同调料的重复操作标识及素食步骤残留肉类文字。首次浏览器检查因Chromium缺少libnspr4/libnss3/libasound而未执行到页面；临时解压依赖后发现错误备份提示使用“不是有效”而检查词表未包含，补正词表，数据保留断言保持不变。

本次隔离环境没有修改系统安装，缺失库只下载并解压在临时目录。相同环境复现可执行：

```sh
mkdir -p /tmp/dual-flavor-browser-libs
(cd /tmp/dual-flavor-browser-libs && apt-get download libnspr4 libnss3 libasound2t64)
for browser_package in /tmp/dual-flavor-browser-libs/*.deb; do
  dpkg-deb -x "$browser_package" /tmp/dual-flavor-browser-libs/extracted
done
env LD_LIBRARY_PATH=/tmp/dual-flavor-browser-libs/extracted/usr/lib/x86_64-linux-gnu npm test
```

正式验收同样在 `python3 scripts/core/delivery_contract.py check …` 前加该环境变量；原工具继续生成真实结果。普通已安装依赖的桌面环境不需要这个临时处理。临时库只用于测试浏览器，产品本身启动不依赖它。

## 父验收退回后的加水回归

2026-10-01父验收指出：玉米鸡肉替换为豆腐或鹰嘴豆后，同一批先随玉米加水，再单独加水，与两份采购清单120毫升不一致。文字导出也包含两个操作。原检查只确认蛋白替换、食材排除及文本包含步骤，不能证明操作量一致；这段失败记录保留为历史。

本轮保留原断言，新增4项引擎检查和3项真实浏览器检查，当前共12项引擎、10项浏览器检查。测试均使用合成输入，未执行真实烹饪。

| 范围 | 新增检查 |
| --- | --- |
| 玉米原鸡肉、整桌素食豆腐、素食且排除大豆鹰嘴豆 | 各覆盖A/B为1/1、2/1、2/2、4/1、4/2，共15种配置；采购主菜水为每份60毫升 |
| 每批最多2份 | 检查全部主菜批次的顺序、份数、分配比例和明确毫升数；3份、5份末批为1份60毫升；所有批次加水总量等于采购量 |
| 防止第二次加水残留 | 扫描实际操作句中的主菜水动作，要求每批一次；同时排查同一句重复动作和旧的不带具体水量的第二加水句，而非只匹配新增句子 |
| 全部现有菜单与其他替换 | 原菜单、素食、排大豆方案均检查主菜水；原食材排除案例追加检查番茄换南瓜、蘑菇换西葫芦、鸡蛋换熟鹰嘴豆和鸡肉换豆腐后的水量 |
| 真实网页与txt下载 | 经UI选择生成，读取渲染出的采购行和全部步骤；读取浏览器真实下载文件，逐步比对标题、顺序与操作文字，并独立检查下载中的水量和加水次数 |

这些新增检查已写入测试文件，但本段不预写通过。最终结果由协调器在原交付合同的正式运行器中执行并记录；它们只能证明所覆盖的清单、操作与导出一致，不能证明家庭实烹口味、熟度、设备适配或不存在其他缺陷。
