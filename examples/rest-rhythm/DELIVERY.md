# 缓步 · 城市探索手账

简体中文本地浏览器产品，帮助旅行准备者把自己的恢复节奏、想保留的活动、主备恢复点与返回路线编成一日时间轴。支持任意城市的用户自填资料；不依赖账户、付费API或实时服务。

## 本机启动

在本产品目录执行：

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory .
```

保持终端打开，浏览器访问 `http://127.0.0.1:8080`。关闭终端或按Ctrl+C停止。需要HTTP入口加载JavaScript模块，请勿直接双击HTML。该服务只监听本机，不是公开部署。运行时不需要npm；Node 20以上及npm仅用于开发测试。

## 完整操作

1. 填写城市、旅行日期、出发地点、开始与最晚返回时间。暂不支持跨午夜。
2. 添加1—4位同行人，逐人填写连续活动上限、最短恢复时长和座位、独处、光照、安静需求。编排采用最短活动上限与最长恢复时长。
3. 按希望顺序添加1—20项活动，填写活动时长和抵达此站的转场分钟；包括从出发点到首站的转场。勾选必选和室内，补充开放时间、来源网址与备注。长活动可以分段，系统保留真实的恢复点往返估计，不凭空在展厅休息。
4. 填写主要及可选备用恢复点。转场分钟是从任意活动到该点的保守单程估计，往返均计入负担。填写环境条件、资料来源及核验日期。硬条件未知时不会标成可执行；请核验或更换地点。主点不符合硬条件时可用符合条件的备用点。
5. 填写返回目的地、从任一活动返回的保守分钟与路线说明。退出路程自身超过连续活动上限时必须缩短路线或另找沿途恢复点；系统会明确显示不可行。
6. 点击“编排我的一天”，检查时间轴、未满足条件和未完成活动。绿色状态仅表示自填数据上的节奏可编排，现场仍需确认。
7. 途中先标记完整做完的活动，填写当前时间，再设置额外延误、雨天、主恢复点不可用或提前返回。点击“重排剩余安排”。已标记完成活动时必须填写当前时间，已完成的活动不会再次安排；系统保守安排一次恢复后继续。当前时间应包括已经走过的时间，延误在当前时间后追加；重复点击不累加延误。
8. 保存草稿后刷新可恢复。JSON备份保留输入、完成记录和现场调整，可导入继续编辑。“导出中文手账”生成.md文本，“打印 / 存为PDF”生成当前安排的携带版，包含现实确认项和未完成目标。

途中补充备注、来源、核验日期，或修改活动与恢复条件时，旧时间轴会失效，需要重新编排；已完成活动、当前时间、延误、雨天、恢复点失效及提前返回值继续保留。现场调整和取消完成入口仍可操作，JSON备份也保留这些记录。重新编排会按新的条件核验余下活动，不把已经发生的完成事实重新安排。

修改现有活动名称和约束视为更正同一项活动；如果想更换为另一项目，请添加新活动。已完成活动不能直接移除，先在随身页取消它的完成标记，再删除。载入构造示例、恢复另一份草稿或导入JSON属于替换整份手账；已有现场记录时会先提示确认，取消保留当前工作，无效JSON不会替换输入。

“恢复原定安排”会清除完成标记与现场调整，重新编排原输入；需要保留现场记录时先导出JSON。“恢复已保存草稿”覆盖当前编辑内容；“清空本地草稿”只删除浏览器保存，不删除当前编辑内容。

## 边界与失败恢复

| 情况 | 行为与恢复 |
|---|---|
| 资料未知、不满足硬条件 | 列出条件与未完成必选目标，保留可行的退出动作；核验、换地点或调整条件后重新编排 |
| 开放时段、恢复往返或返回时限容纳不下 | 不把部分活动当完整完成；保留必选输入及失败原因；可延长时间、缩短活动/转场或移除可选项 |
| 雨天 | 略过室外项目，室外必选仍明确未完成；请在输入中添加室内替代，不自动编造地点 |
| 主恢复点不可用 | 使用符合硬条件的备用点；无合格备用时阻止继续活动，不假装就地可休息 |
| 当前时间已超过返回时限 | 明确无法按时返回；需现场调整交通或寻求实际帮助，软件不能提供现实救援 |
| 资料修改后结果失效 | 保留完成事实和现场调整，补齐当前时间后重新编排；若新约束不可行，显示未满足目标，继续修正输入 |
| 移除已经完成的活动 | 明确阻止，保留记录；先取消对应完成标记再移除，或导出备份后明确恢复原定安排 |
| JSON错误、版本不支持、危险字段、超出200KB | 中文提示，保留当前输入；用正确备份重试。界面先拒绝大于500KB文件，核心格式总限额200KB |
| 浏览器存储不可用或草稿损坏 | 继续编辑、编排与下载；使用独立JSON备份恢复。隐私模式或浏览器清理可能删除草稿 |
| 转场估计不适用于所有活动 | 使用最大保守估计，或拆成独立计划；当前版本不做逐地点地图路径计算 |

## 隐私与现实限制

资料仅保存在当前浏览器localStorage（键`rest-rhythm-draft-v1`），以及主动下载的文件，不上传。来源链接只在主动点击时打开外部网页。不同端口/浏览器不共享草稿。

构造示例中的地点、资料与条件均非真实核验，不是可直接执行的行程。用户标注符合也只是个人准备假设，不保证空座、独处、噪声、路线、开放、天气、票额、实际恢复效果或安全。产品不提供诊断、专业陪伴、预约、实时导航或现场支持。

原评估保存在历史运行，没有被软件交付覆盖；该历史材料未随独立副本公开。没有真实用户采用、交易、收入、获客或盈利证据。软件检查使用构造数据，不代表实地出行体验。

## 维护与检查

`core.js` 是纯编排与 JSON 校验，`app.js` 负责编辑、状态保存与导出。`index.html` / `styles.css` 负责界面。在本产品目录执行：

```sh
npm ci
npx playwright install chromium
npm test
npm run test:browser
```

浏览器检查使用 Playwright Chromium。Windows 测试服务器使用 `python`，其他平台使用 `python3`；不依赖原运行路径或临时安装目录。离线环境需预先具备对应浏览器，Linux 还需浏览器系统库。安装依赖不等于检查通过；本产品运行不需要测试依赖。构造输入测试不证明实际旅行或恢复效果。
