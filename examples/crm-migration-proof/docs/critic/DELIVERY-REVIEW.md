# CRM 迁移验收交付反证审查

支持已授权的本地产品交付；核心要求是防止把两份导出的一致误称为真实 CRM 迁移完整。

本审查基于原 `docs/evaluation/RESULT.md`、14 场景合成实验及随后产品源代码。旧实验支持所给材料中的异常检查，不证明真实业务适配、真人使用、收费或节时。原机会评分与商业投入判断不因本次软件交付改写。

## 最可能造成虚假通过的三类失败

| 风险 | 具体失败场景 | 必须落实的防线 |
|---|---|---|
| 身份与关系被错误归一化 | 把 `001` 转成 `1`，或重复目标 ID 被字典覆盖，关系错挂后仍按错误身份比较 | ID 全程字符串；源键、目标新键、目标旧键分别查重；关系端点经可靠新旧 ID 映射还原；孤儿和重复关系独立列出 |
| 数值与转换掩盖真实差异 | 两笔金额一增一减，总额不变；浮点舍入掩盖分以下变动；未授权把 inactive 映成 active | 逐记录精确十进制比较；拒绝 NaN/Infinity；按声明精度查验；合法状态、日期、空白与大小写转换须明示授权 |
| 不完整或过期材料冒充完整验收 | 源与目标同时缺一批记录但比较一致；关联文件未导出；修改输入后仍下载旧的通过报告 | 缺全量范围、可靠映射、关联或转换授权时不可判定；声明不等于核实；快照/范围入报告；输入变动后旧报告失效 |

## 必须满足的交付条款

| 项 | 可观察要求 |
|---|---|
| 输入契约 | 可配置对象与关系的源/目标 CSV 真实上传或粘贴和自定义字段映射；无法解析、缺必需列、重复表头、行列数异常给出可修正提示，不静默吞行 |
| 稳定身份 | 对象按源旧 ID 对齐，目标主键选择 `legacy_id` 等可靠旧 ID；目标关系端点由使用者预先还原为所选身份；不凭姓名、邮件或行顺序猜测；未纳入目标原生新 ID 时不能声称已检验该列唯一性 |
| 逐项检查 | 记录遗漏/新增、重复键、字段差异、关系错挂/孤儿/重复、币种、逐笔金额与精度都进入报告；总额只作辅助 |
| 判断边界 | 通过限定为本次输入、已声明范围和授权规则；缺证显示不可判定，已发现差异不因不可判定而隐藏 |
| 用户声明 | 完整导出、快照可比、稳定身份和转换授权均为用户声明；软件不能独立核实真实 CRM 或授权人的资格 |
| 输出证据 | JSON 与中文报告含文件哈希、字段映射、转换规则、范围、问题和未知；下载结果与屏幕结论同一版本 |
| 恢复 | 修正文件、字段映射或声明后能重新运行；未运行的新输入不能下载先前通过结论 |
| 安全呈现 | CSV 内容、文件名、scope/notes 等视为普通文本，不作为 HTML 执行 |
| 交接 | 中文操作文档说明支持格式、完整核心流程、失败恢复及真实 CRM 未连接；演示数据标为合成 |

## 实现审查记录

初始时仅有产品仓库骨架，以上是交付前必需条款。功能检查仅由协调器通过程序指定 runner 执行；本角色的静态审查不是测试通过证据。

首次 `engine.js` 静态审查发现如下问题，已发送协调器与实现方修正：

| 发现 | 影响 | 修正要求 |
|---|---|---|
| 关联键仅含两个端点，不含 `role` | 角色改变可能通过；同端点不同合法角色误报重复 | 增加可选两侧角色列并纳入关联身份键，遗漏角色语义必须明确边界 |
| 未读取 `scope.relationships` | 标记关系未纳入后可能整体通过 | 未确认关联范围时保留不可判定 |
| 值映射校验在共同记录循环内部 | 空表或无共同 ID 时非法映射可被忽略 | 在配置阶段验证映射，不依赖数据是否匹配 |
| 金额仅数值等价比较，没有最大精度规则 | 源目标同样含 `100.101` 时不发现两位小数契约违规 | 增加明确精度契约，独立验证双方值，不靠差异推断合法性 |

尚未运行功能检查，以上来自对实际代码路径的静态阅读，不是捏造的运行失败。

首轮实现已增加角色列、金额允许小数位、缺关系范围的未知项，并将映射校验前移。随后 `app.js` 静态审查发现新风险，已发送协调器：

| 发现 | 影响 | 修正要求 |
|---|---|---|
| 文件读取前未同步进入读取状态 | 新文件读取期间仍可生成旧数据报告，并发选择可能被旧读取覆盖 | 从文件选择事件同步清除该侧旧材料、禁用生成并建立读取令牌，直到完整读/解析/哈希结束 |
| 编辑粘贴框仅清旧报告但保留旧表 | 未应用粘贴内容时再次核验使用旧表 | 明示待应用状态，未应用时阻止生成或移除该侧旧表 |
| 异常 CSV 被重复添加 BOM | 导出开头产生两个 BOM，影响部分工具读首列 | `toCSV` 与 UI 只由一侧添加 BOM |
| 金额映射后的值才验证精度 | 人为金额映射可把原始超精度值掩盖成合法值 | 先独立核验原始金额精度，或明确禁止金额值映射 |

再次静态核对确认：关联已可选角色列及授权 JSON 映射；金额默认允许两位小数、可设 0 至 8；不接收非法配置精度；关系排除保留未知；坏字段映射在配置阶段检查。UI 已在上传完整异步读取前设置令牌、清除旧侧数据、禁用生成，并阻止未应用粘贴内容；异常 CSV 仅添加一个 BOM，用户输入在报告中转义显示，未知和全部异常进入导出。以上是代码审查结论，实际执行以协调器正式检查记录为准。

追加建议：合成样例生成哈希时同样进入读取状态，防止哈希尚未补齐就生成证据；上传哈希须对应原始 UTF-8 字节或准确注明解码文本口径，尤其保留 BOM 的差异。

## 剩余业务边界

真实 CRM 的导出完整性、字段业务意义、合法合并/拆分、活动/附件、非双射映射及跨快照业务变更仍需人工判断；没有真实客户或交易。新交付解决的是明确 CSV 契约下的证据生成，不新增自主商业投入结论。
