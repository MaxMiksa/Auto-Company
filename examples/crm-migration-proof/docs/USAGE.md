# CRM 迁移验收证据工作台使用说明

本工作台帮助实施顾问比较迁移前后的联系人、交易和关联 CSV，生成带范围、异常与未知项的本地验收证据。它未连接真实 CRM，不能证明导出完整、业务授权有效或客户已经验收。内置示例完全为合成材料。

## 准备材料与身份

请导出同一验收范围和可比较快照下的源、目标 CSV。每个对象配置一对 CSV，可上传文件或粘贴 CSV；支持添加对象与关系组。字段值按文本保留，ID 中的前导零不可删除。下面是联系人、交易及关联的示例约定，不是必须照用的列名。

| 材料 | 默认字段 | 用途 |
|---|---|---|
| 源联系人 | `contact_id,name,email,stage` | `contact_id` 是源系统稳定旧 ID |
| 目标联系人 | `record_id,legacy_id,display_name,email,status` | `record_id` 是目标新 ID；`legacy_id` 必须保存对应源旧 ID |
| 源交易 | `deal_id,amount,currency,close_date` | `deal_id` 是源系统稳定旧 ID；金额保留精确十进制文本 |
| 目标交易 | `record_id,legacy_id,value,money,closed_on` | `record_id` 是目标新 ID；`legacy_id` 必须保存对应源交易旧 ID |
| 源关联 | `deal_id,contact_id,role` | 端点使用源旧 ID，支持同一交易的多个联系人与角色 |
| 目标关联原始导出 | `transaction_id,person_id,role` | 若端点使用目标新 ID，必须先按可靠映射还原为源旧 ID，再交工作台检查 |

例如，源联系人 `001` 迁移成目标 `C11`，目标联系人行应包含 `record_id=C11,legacy_id=001`；联系人对象的源主键选 `contact_id`，目标主键选 `legacy_id`。导出的目标关联若为 `person_id=C11`，须先用实体的新旧 ID 映射把它还原为 `001`。交易端点也按同样方法还原。工作台要求关联端点已经使用所选对象主键的身份值，不会自动猜测或替你还原。`legacy_id=1` 不等于 `001`。不得只凭邮件、姓名、行号或相似度猜测身份。

源旧 ID、目标新 ID、目标 `legacy_id` 均需在所属实体表内唯一。工作台检查选择的源、目标主键；若未单独纳入原生新 ID，它不独立验证该新 ID 的唯一性。准备新旧映射时请先人工或用既有数据流程查明重复。当前支持一对一稳定身份映射，不支持合法合并、拆分或多对一自动验收。关联端点必须存在；重复或孤儿关联需要复核。

每个比较字段选择源列、目标列与类型，可增删字段映射。文本、邮件、金额、日期采用各自明确规则；目标值到源值的映射使用 JSON 对象，例如 `{"A":"active"}`。金额字段还需选择源、目标币种列。关系组选择起点、终点对象及对应的两侧端点列；需要比较关系角色时按页面提供的角色列配置，不要丢掉会影响业务含义的角色。

金额允许小数位默认 2，可按项目规则设为 0 至 8 的整数；比较不舍入，非零尾数超过所选精度会报异常。`100.200` 与 `100.2` 表示相同数值，尾随零不算新增有效精度。关系角色列可选：配置后，端点与角色共同组成关系身份；未配置则只核验端点，报告不能证明角色正确。同一端点有不同角色时，应配置角色列以免把它们误作重复关系。目标角色可用页面上的 JSON 值映射统一到源口径，例如 `{"P":"primary"}`，该映射也必须获得授权。

## 完成一次验收

1. 打开本地工作台；初次可载入合成样例了解完整流程。
2. 添加并上传或粘贴自己的源、目标对象 CSV；粘贴后点击“应用粘贴内容”。选择稳定源旧 ID 与目标 `legacy_id` 主键，添加需要比较的字段映射。若有关系，先将目标关联端点还原为旧 ID，再添加关系组与对应 CSV。
3. 填写验收范围、快照口径及转换规则，逐项确认完整导出、稳定身份、转换授权与快照可比性。勾选只是记录你的声明，不代表工作台已经独立核实。未纳入关系时也要在报告中保留这项未知。
4. 执行检查，先读整体结论，再逐表复核差异、身份、金额与关联问题以及未证明项。
5. 下载本次中文证据报告与结构化结果，保留原始导出、映射、授权和人工复核依据一起交接。
6. 修正数据或声明后重新检查。输入变更后的旧结论不能用作新输入的验收结论。

粘贴框可先填写两侧或多个对象，再分别点击“应用粘贴内容”。应用一侧、添加或删除字段映射、调整其他对象时，尚未应用的文本和展开状态会保留，文件信息位置继续显示“粘贴内容尚未应用”。成功应用的文本也保留供复核；编辑后必须再次应用，即使把文本清空也不能继续核验旧表。应用失败时纠正保留的文本后重试。

成功上传文件会替换本侧材料并清空本侧粘贴草稿；上传失败保留已有草稿供恢复，其他侧草稿保持原样。草稿只存在当前页面内：主动移除相应对象/关联表、清空、载入样例或刷新会丢弃相应草稿，请在操作前自行保留所需文本。

## 转换与金额规则

合法格式转换须明确声明并获得项目授权。示例包括姓名仅去首尾空白、邮件大小写统一、目标 `A` 对应源 `active`、日期格式变化。状态映射只表达已授权的等价转换，不能把实际业务状态变更藏在映射里；例如 `inactive → active` 需要真实业务规则支持。

金额逐笔精确比较，不用浮点容差，也不只比较总额。`100.10` 与 `100.1` 数值相同；`100.101` 不会悄悄舍入为 `100.10`。一笔增加、另一笔减少即使总额不变也属于差异。不同币种不能互相抵消；工作台不做汇率换算。ID、币种和关联角色的改变不是可自行忽略的格式变化。金额及日期两侧均为空时视为相同，工作台不代替业务必填规则检查。

## 结论与人工复核

| 结论 | 含义与后续动作 |
|---|---|
| 通过 | 所给材料在声明范围和授权规则下未发现阻断项；仍需人工复核输入完整性、规则授权和业务意义 |
| 失败 | 发现缺失、重复、字段、金额或关联等明确问题；定位问题并修正后重跑。若同时缺证，报告仍保留未知，不能据此声称范围已核实 |
| 不可判定 | 尚未发现明确异常，但缺少必要文件、身份映射、范围/快照依据或转换授权；补齐依据后重跑 |
| 输入错误 | 无法可靠读取或解释输入；按错误提示修正 CSV、字段映射或规则后重跑，不能把报错当无异常 |

两份相同的局部导出可以比较一致，但不能证明全 CRM 完整。Scope 声明必须说明对象、筛选条件、字段、关联范围和时间口径，并由实施人员保存相应导出依据。软件不能自动发现源与目标同时未导出的记录、附件或活动。

人工复核至少覆盖：旧 ID 映射来源；导出筛选和快照差异；状态与格式转换授权；关联角色业务含义；逐条异常的处理依据。不要仅凭总数、总金额或绿色结论签署真实迁移验收。

## 输入错误与恢复

| 提示或异常 | 修正方式 |
|---|---|
| 缺必需列或映射不正确 | 检查 CSV 表头，重新选择实际字段；勿将两个不同业务字段误映到同一列 |
| 引号、编码、列数或表头错误 | 以 UTF-8 CSV 重新导出，正确引用含逗号/换行/引号的内容，不手工截断坏行 |
| 重复 ID | 在 CRM 或导出流程中查明重复来源；不能靠删除任意行掩盖实体合并 |
| 目标关联端点找不到 | 从目标实体的新 ID 与 `legacy_id` 建可靠映射，先把关联端点还原为所选目标主键值，再上传；不要混用新旧 ID |
| 非法金额、日期或映射规则 | 修正为支持的明确格式，保留原始值；不得将错误值默认为零或今天 |
| 粘贴内容尚未应用 | 点击该侧“应用粘贴内容”，等待读取完成后再生成；编辑粘贴框已移除该侧旧材料，不能沿用旧报告 |
| 缺文件或完整性依据 | 补导出或补齐可靠依据；若范围确无关联也需明确说明，并按页面约定提交含表头的空关系表或标记未纳入范围 |

## 适用范围与隐私

本工具面向 UTF-8 CSV、可配置对象及对象间关联、一对一稳定 ID 映射和明确字段转换。每表最多 5 MiB、20,000 数据行；最多 12 个对象、12 个关联表。只检查选择的字段和关系，未选列不代表已验证。超大导出、活动/附件、重复实体合并或拆分、跨币种折算、自由业务逻辑不在自动验收范围内。不要把一张全量表任意拆成几个包后，将某一个包的通过当作全项目通过；如分批验收须分别保留批次范围、跨批身份与关系复核证据。

数据用于本地浏览器检查，不要求注册、登录或发送给外部 CRM，不自动存储到浏览器。可下载包含配置与文件哈希的 JSON、异常清单 CSV、可打印的中文完整 HTML 报告。下载的证据包含输入摘要与差异数据，可能包含个人资料；由你按项目既有数据处理约定保存和交接。刷新页面或关闭浏览器前请下载所需结果。本工具的本地可用性与合成检查不等于真实用户采用、成交或盈利。
