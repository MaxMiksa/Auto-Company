# 参途界面与交互设计

## 目标与场景

主要使用者是负责混合活动交接的组织者。他需要知道参加者能否从入口走到观看、字幕和提前资料的最终端；发生变更时，需要知道哪些旧承诺失效、由谁恢复、如何重新确认。界面以一条真实参与路径为中心，软件记录人工观察，不替代现场服务核验。

## 视觉方向

采用纸面演练指挥台：暖纸色背景、深墨绿侧栏、中文衬线标题、苔绿行动按钮和警示橙缺口。服务表格承载高密度工作信息，路径用分栏记录页展示，避免通用指标卡片。左侧固定四步导航，在窄屏转为顶部导航；正文与表格保持清楚的中文排版。Logo 为折线路径与最终端圆点，页面与 favicon 使用程序生成的 `/auto-company-icon.svg`。

| 元素 | 用途 |
| --- | --- |
| 苔绿 | 可执行行动、完整通过 |
| 警示橙 | 失败、迟交、未解决缺口 |
| 灰绿 | 证据待补、确认待补 |
| 中文衬线标题 | 活动、服务与路径的纸面层级 |
| 服务表格 | 负责人、当前版本、入口、截止与演练操作 |
| 路径记录页 | 多服务组合、逐项缺口、双向确认 |

## 完整流程

1. 首次进入为空白活动，填写名称、日期与时段。
2. 按时段添加参与入口、字幕和提前资料；资料必须有提前截止。
3. 根据参加者实际需要建立任意非空多服务的参加者路径；组织者核对已完整覆盖需要。后续可调整关联服务，填写原因后重新双向确认。
4. 以参加者方式核验最终端，记录实际观察、核验人、时间与通过或失败结果；资料另记录实际送达时间。
5. 查看逐项缺口，负责人和参加者分别确认当前版本。
6. 发生变更时填写原因，新版撤销受影响路径的旧版就绪；旧证据和历史迟交保留。
7. 分别导出单条路径的参加者指引、指定负责人的任务、全活动中文交接包和完整 JSON；导入失败不修改当前状态。新建或加载合成演示须明确确认替换，并保留上一份本地快照。

## 无障碍与恢复

表单均有中文关联标签；按钮与原生对话框可键盘操作，焦点有明确轮廓。状态采用文字，颜色只是辅助。页面提供跳到工作区链接，移动端表格可横向浏览，路径面板纵向排列；减少动画设置关闭转场。本地保存失败明确提示下载备份，导入错误在对话框内保留输入，原数据不会因失败被替换。

## 浏览器验证定位

资源行包含 `data-resource-id`，路径面板包含 `data-path-id`。主要动作可使用中文按钮名定位：添加时段、添加服务、建立路径、记录演练、变更入口、负责人确认、参加者确认、导出中文交接包、下载完整备份、导入备份。首次空白，演示须显式加载并确认，不能作为真实业务证据。
