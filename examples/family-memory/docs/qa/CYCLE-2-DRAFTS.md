本轮针对 `.continuation/PARENT-REVIEW.md` 的实际退回：同时填写两条回应，只保存第一条后，第二条输入被普通重绘清空。旧浏览器结果及原审查文档保持原样，不把这次修复解释为真实家庭采用、交易或收入。

独立 QA 已读完整 `qa-bach` 角色、任务约束、原浏览器测试、测试入口与修复后的 `app.js`。已新增下列真实浏览器回归；本代理没有执行功能检查。实际通过、失败与截图内容以协调器的正式 `delivery_contract.py` runner 结果为准，本报告在正式检查前冻结。

## 高影响风险与自动检查

| 风险 | 回归操作 | 可观察预期 |
|---|---|---|
| 保存第一条清空第二条，或同题文字共用草稿 | 虚构示例中新建季节、颜色两题，实际同时填写；再新建相同颜色文字但不同编号的第三题；分别保存前两题 | 按问题编号找到卡片，未保存的其他回应完整保留；保存的文字与对应编号匹配；生成 `multiple-answer-drafts.png` |
| 步骤或无关条目重绘清草稿 | 切换四步、新增参与者、保存其他原话、取消及保存该原话修订 | 其他回应、未保存活动标题、原话输入、问题文字及出处选择、故事标题/注记/分歧及出处选择保持原值 |
| 跳过仍保留可复活的回答 | 两条文字相同但编号独立的问题分别填写，只跳过其中一题 | 被跳过题无回答框且草稿不进入缓存、导出与打印；另一题仍有原输入 |
| 问题撤回误清全部草稿，或取消也清输入 | 先取消撤回再确认撤回一题 | 取消时两题输入完整；确认后只删除相应问题，其他草稿继续保留 |
| 来源撤回只清第一层，派生回答草稿残留 | 原话 → 已保存问题回答 → 引用该回答的新问题，另有独立问题；撤回最初原话 | 两层关联问题均消失，独立回答框保留；被清理草稿不在当前 DOM 输入值、缓存、JSON、Markdown、打印中 |
| 参与撤销仅按被问者清理，忽略其原话的关联问题 | 三名虚构参与者，分别填写直接问撤销者、其他两人引用其原话互问、其他两人无来源互问；撤销一人后再重新同意 | 直接和来源关联问题均清理；其他人的独立问题与回应草稿保留；重新同意不恢复旧问题 |
| 失败操作提前清理用户输入 | 提交空白回应、导入损坏 JSON、取消合法导入 | 两个回答框保留原值；无效导入保持原活动备份完全一致 |
| 活动替换或撤销重新带回旧草稿 | 成功导入、撤销导入、清空与撤销、载入示例与撤销；恢复含原问题编号的旧备份 | 恢复可重新出现同一编号的未回应问题，回答框为空；旧草稿不会复活 |

新增 6 个测试场景使用合成材料，通过真实页面输入、按钮、下载、导入与打印操作检查；不直接读写内部 Map，也不把纯函数调用替代浏览器路径。撤回测试先验证无关草稿保留，再做活动替换；替换整体清空草稿与撤回局部清理是不同的预期。

## 修复后静态复核

| 实现观察 | 判断 |
|---|---|
| 回答草稿按 `question.id` 存入页面内存，输入事件更新，重绘回填 | 避免按列表位置或问题文字混用；普通 DOM 重建有恢复来源 |
| 成功提交先验证下一状态，再清除不再处于待回应状态的问题草稿 | 保存、跳过及问题删除能收回对应草稿；无效回应在验证失败时不清其余输入 |
| 原话与参与者的变化使用现有关系识别受影响问题及固定表单 | 未看到恢复已被来源递归删除的问题路径；无关回答草稿有明确保留条件 |
| 清空、成功导入、示例替换和撤销替换显式清全部草稿 | 即使恢复旧问题编号也没有旧回答草稿回填来源 |
| 取消确认和坏备份退出发生在整体草稿清理之前 | 静态逻辑支持取消或失败保留，仍须正式浏览器确认 |
| 草稿不加入活动对象、持久化或导出；有非空回答草稿时触发离页提醒 | 无新增私密草稿落盘路径；离页提醒不等于持久保存 |

本次静态复核未发现需要阻断正式回归的残留路径。该判断不代替实际执行，也不承诺不存在其他缺陷。

## 保留边界与探索性关注

未保存回应只在当前页面内存中保留；确认刷新或关闭仍会丢失。原生离页提醒取决于浏览器与用户是否已有交互，不能承诺所有设备都会弹出。完整备份只包含已保存活动，不含当前草稿，这一边界须在操作说明中保持明确。

没有语义识别手工复制：若将已撤回原话复制到无引用的独立回答草稿，关系清理无法识别其内容归属。产品已有自行检查手写文字及旧导出副本的提示；不应为了声称自动清理而重新清空全部无关草稿。当前页面以外的下载、打印与旧备份无法自动收回。

多标签页状态冲突、浏览器终止进程、不同浏览器对离页提醒的差异仍是恢复边界。本轮集中检查已退回的同页输入丢失与撤回泄漏，不将这些未执行的探索描述为已通过。
