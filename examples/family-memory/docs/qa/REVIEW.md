## 核心使用流程应满足的条件

| 用户任务 | 可观察结果 | 高影响反例 |
|---|---|---|
| 主办者开一场活动，亲属自愿署名 | 活动标题、主题、参与者可编辑；允许不参与 | 未同意者被默认纳入、匿名片段被错署名 |
| 同设备轮流记录原话 | 原话与作者保持绑定，可编辑、可撤回 | 改姓名使旧片段丢失归属；空白原话进入故事 |
| 对原话互问，答复或跳过 | 问题有明确目标；答复与答复者可追溯；跳过不中断 | 答案误署名；跳过被当成同意；删除目标后问题孤立 |
| 手动共同故事并列不同说法 | 每个结论可回到引用原话，分歧保留各自署名 | 合成“事实”覆盖分歧；自由文字声称是逐字原话 |
| JSON 备份与恢复 | 合法备份完整恢复；错误文件保留当前活动 | 导入一半后失败；不匹配版本、悬空引用与重复 ID 被接纳 |
| Markdown 与打印留存 | 可读、中文、署名、引用和分歧一致 | Markdown 隐藏未导出隐私；打印按钮实际只展示样例 |
| 编辑、撤回和清空 | 新成果同步更新或明确要求重写；撤回清理所有当前派生材料 | 原话已删，旧标题、故事、问答、浏览器存储仍泄漏 |

## 实现复核结果

已静态阅读 `core.js`、`app.js`、`index.html`、`style.css` 与中文 `README.md`、`DELIVERY.md`，并检查功能与浏览器测试源码。审查代理没有运行检查；真实检查结果以协调器正式 runner 为准。

| 代码观察 | 结论及限制 |
|---|---|
| `validateSession` 重建规范对象，限制文本、集合和引用，检查重复编号、同意状态、公开原话及答复署名一致性 | 能拒绝主要损坏输入；正式 runner 仍需验证错误恢复不覆盖 UI 当前活动 |
| 写操作首先调用 `validateSession` 获取副本；`importJSON` 全量解析和校验后才返回状态 | 函数层面没有“修改一半后失败”的原活动覆盖路径；UI 赋值和存储行为待看 |
| `invalidate` 递归删来源问题及回答原话；受影响故事清除标题、注记及不同说法，最后一条来源被撤回时删故事 | 代码针对历史派生标题泄漏作了实际处理；不能识别无引用手写副本 |
| 修改公开原话后恢复可追溯编号，同时把相关故事设为“待重新核对的故事”并清注记/分歧 | 修订不会直接继续沿用旧结论；须检查 UI 能提示并允许重写 |
| Markdown 对 HTML 与 Markdown 链接语法转义，只从公开原话构建 | 未看到直接执行输入 HTML 的函数路径；打印及 DOM 渲染另需检查 |
| JSON 保留私密原话；撤销参与保留称呼但清个人原话及关联内容 | 交接已准确披露这两点，并提示手写副本和旧导出无法自动撤回 |
| 交接明确文字输入、同设备、无录音转写、无远程协作及用户/收入为 0 | 当前说明没有把本地软件交付扩大为真实活动或商业成功 |

已阅读 `index.html`、`style.css` 和初版 `app.js`。页面采用逐节点 `textContent` 创建，未见输入传入 `innerHTML`；文件名清理路径字符。布局有手机单栏断点、输入 16px、可见焦点、跳转主内容和减少动效规则；实际溢出与交互仍由浏览器检查确认。

### 初版代码发现与修复复核

以下为静态代码确认的路径，尚未声称浏览器执行观察：

| 发现 | 复现路径与依据 | 要求 |
|---|---|---|
| 异步导入清理访问已失效的事件目标 | `import-file` 的异步监听先 `await file.text()`，最后 `event.currentTarget.value = ''`；事件派发结束后 `currentTarget` 为 null | 监听开始先捕获 input 节点，后续始终用捕获变量；成功/失败导入不得出现未处理异常 |
| 空字符串损坏缓存没有进入保护模式 | 本地存储 key 存在但值为 `''`，`importJSON` 失败后以 `rawCache !== ''` 判断，使损坏内容被当成无缓存 | 独立记录缓存是否存在，空值也须保护并保留原始内容 |
| 打印后旧派生 DOM 可能继续保留 | 打印先构建 `print-content`；撤回或编辑的 `render` 未清该容器 | 更新当前状态时删除陈旧打印 DOM，重印时从新状态构建 |
| 活动替换保留旧互问草稿 | 清空/恢复/示例替换只 reset 原话与故事表单，第三章文本未清 | 替换活动及隐私撤回时清理旧问题草稿与来源选择 |
| 编辑原话时讲述者禁用状态可被下一次 render 覆盖 | `editMemory` 禁用讲述者，但 render 末尾统一设 `control.disabled = blocked` | 渲染后保持编辑讲述者不可改，避免选择新署名后实际保存仍保留旧署名的误导 |
| 无来源问题的手误或敏感副本无法定点撤回 | 新建 `sourceIds=[]` 的现场问题，进入待回应或跳过；初版 UI 无编辑/删除问题入口，且该问题仍进 Markdown/打印 | 提供撤回问题入口，并清理该问题回答原话及进一步派生内容，使“自行删改”边界成为可操作流程 |
| 撤回后仍可能通过前一活动快照恢复旧敏感内容 | 恢复/清空/示例建立 `undoState`，随后普通修改和撤回未失效它 | 普通修改使一次恢复快照失效，并明确撤销只在下一次修改或关闭页面前有效 |

上述已反馈界面开发者与协调器，随后逐项重新阅读实现：

| 项目 | 最终静态复核 |
|---|---|
| 异步导入事件目标 | 改为监听开始捕获 `const input`，最后使用 `input.value`；有效及错误文件仍在完整校验后处理 |
| 空字符串坏缓存 | `rawCache` 以 null 表示不存在；存在但空的缓存会进入保护模式，保留下载原缓存与确认重开的入口 |
| 打印旧 DOM | `render` 首先清空 `print-content`；打印从当前有效状态重建，并仅选公开原话 |
| 旧问题及编辑草稿 | `resetDrafts` 清原话、故事及问题表单；活动替换、来源修改与隐私撤回调用它 |
| 编辑讲述者 | `render` 在统一状态后重新禁用编辑原话的讲述者，保存仍保持原署名；参与者称呼现可另行修改 |
| 撤回现场问题 | 新增 `removeQuestion` 与每张问题卡“撤回问题”；清其回答原话及递归派生，保留问题原始出处原话 |
| 旧恢复快照 | 普通 `commit` 清 `undoState`；仅清空、导入及虚构示例替换保留一次；中文提示和交接准确说明有效期 |

## 最终独立判断

**可进入正式功能与浏览器验收；本次静态复核未发现仍未处理的代码阻断。** 页面入口提供真实输入、四步活动、原话/故事修改、问题/原话/参与撤回、备份恢复及导出，不依赖硬编码示例完成核心任务。

剩余必要验证是实际浏览器中的完整自建活动、手机不溢出、输入不执行、打印与新导出无已撤回标记、坏缓存保护、拒绝存储时可备份、恢复后无未处理异常。测试源码覆盖这些方向，但此处不提前写“通过”或测试数量。正式 runner 与交付合同独立决定验收状态。
