# 回应草稿修复

## 问题与结果

保存任何条目都会调用 `render()`，原先的 `renderQuestions()` 直接重建全部回应表单，未提交的文字随旧节点被删除。因此同时填写两个回答时，仅保存第一个就会清空第二个。

现按问题编号在当前页面内存中独立保留回应草稿。普通保存、其他条目操作引起的重绘和步骤切换不会清空仍待回应的问题。保存成功或主动跳过时清除本条草稿；输入校验失败时保留输入。没有新增依赖，也没有改变活动备份格式。

## 保留与清理范围

| 操作 | 草稿处理 |
| --- | --- |
| 保存回应、跳过问题 | 清除本条，其余待回应草稿保留 |
| 新增条目、修改称呼、取消原话编辑、切换步骤 | 保留其他回应和未提交表单；选择仍有效的来源保持勾选 |
| 撤回问题、撤回或修订原话、撤销参与 | 清除已失效问题的回应草稿；重置引用受影响来源或参与者的原话、提问、故事表单；无关草稿保留 |
| 清空活动、加载示例、成功导入、撤销活动替换 | 清除当前全部草稿，不随旧活动快照恢复 |

关联草稿因撤回或范围变化清理时，操作提示明确说明清理结果。原话或故事编辑成功只重置本条编辑表单，再按数据变化清理关联范围。参与撤销不会将已撤回的原话、回答或关联故事文字通过草稿带回。无法按语义识别手动复制到无引用字段的相同内容，既有界面和交接中的人工检查边界仍适用。

固定的活动、参与者、原话、提问和故事表单没有在普通重绘中重建；原有值继续保留。新增草稿保存只用于会重建的回应框。

## 保存边界与检查

草稿仅保留在当前页面内存，不写入本地存储、完整 JSON 备份、故事导出或打印。互问章节提示刷新或关闭前逐条保存；存在非空回应草稿时，`beforeunload` 请求浏览器显示离页提醒。浏览器是否显示此提醒由浏览器策略决定，不能替代主动保存。确认刷新或关闭后，草稿不会恢复。

本次开发已用 `node --check app.js` 检查语法。针对真实浏览器并行填写多个回答及隐私清理的回归由 QA 成员维护；正式检查和交付证据由协调器统一登记，本说明不代替其检查结果。
