# 双向披露批次验收：检查策略与边界

本文件记录本地构造材料的检查设计，设计本身不能作为通过证据；正式结果以交付检查工具登记的运行记录及框架 `docs/delivery` 中的执行报告为准。本文写入时尚未运行检查。所有 PDF、姓名、秘密标记和复核文字均为合成数据，不代表真实客户或真实采用。

| 主要风险 | 需要观察的行为 | 验证方法 |
| --- | --- | --- |
| 遮盖被当作删除 | 黑框下可提取文字仍明确失败 | 构造真实 PDF 的页面文字与绘制覆盖 |
| 删除遗漏其他层 | 元数据、批注、附件存在秘密时指出位置；未检查层不能默认为通过 | 构造真实 PDF 的各层内容 |
| 双向规则失真 | 应保留事实缺失时失败；中文可提取文本正确匹配；矛盾规则拒绝 | 中文正文、过删材料、同值删除和保留规则 |
| 扫描件被误认证 | 无文字图像材料进入人工复核，明确检查覆盖边界 | 将真实 PDF 页面渲染后嵌为图像 |
| 批次污染 | 损坏或加密文件不影响其他文件结果 | 混合批次 HTTP 调用 |
| 复核无效重用 | 文件或规则版本改变后原复核失效 | 文件哈希、规则哈希、修改与重跑 |
| 异常输入 | 空输入、过大值、错误类型、重复与冲突规则均有可恢复错误 | 实际函数和 HTTP 输入 |
| 本机入口暴露 | 非本机 Origin、路径遍历与非授权静态文件被拒绝 | 真实回环 HTTP 服务请求 |
| 前端与导出脱节 | 上传、规则、检查、人工复核、导出、复用和失效可真实完成 | 实际浏览器流程 |
| 结果注入 | 文件名、规则或批注的 HTML 特殊字符以文本呈现；导出不执行脚本 | 合成脚本标记与浏览器探针 |

## 执行约定

- 自动化采用 Python 标准库 `unittest`，PDF 由产品已有的 PyMuPDF 依赖现场构造，不修改历史实验。
- 功能检查由协调器通过 `delivery_contract.py check` 调用，不另行重复执行只为登记结果。
- 浏览器检查采用已安装的 Playwright；若浏览器依赖不可用，记录准确限制，不以静态文件存在替代操作证据。
- 不宣称穷尽所有 PDF 隐藏结构、OCR 或取证；通过仅描述已定义规则及已覆盖的本地检查，例外需人工判断。

## 正式执行结果

由协调器在框架 `docs/delivery` 登记实际运行记录、结论和残余限制，避免正式检查后修改产品而使检查指纹失效。

## 检查入口

`tests.test_workflow.CoreFlowTests` 观察双向匹配与多层泄漏；`FailureRecoveryTests` 观察错误输入、单文件隔离与容量边界；`HttpWorkflowTests` 观察真实服务请求；`BrowserWorkflowTests` 观察真实页面操作。协调器用交付合同工具的 Python unittest 适配器按对应类别执行。浏览器需安装 Playwright Chromium，运行时设置 `PLAYWRIGHT_BROWSERS_PATH=/tmp/disclosure-qa-browsers`；缺失依赖会实际失败，不使用跳过作为通过。
