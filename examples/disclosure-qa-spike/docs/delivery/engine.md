# 检查引擎与本地接口

产品入口为 `python server.py --port 8765`，固定监听 `127.0.0.1`。页面和接口使用同一来源；拒绝远程 Host、跨站来源、路径穿越和超大请求。原 PDF、规则与检查结果均不写入服务端磁盘；报告由用户在浏览器主动导出。进程退出即结束本地服务。

## 输入与结果

`POST /api/check` 接受 JSON：`batch_name`、`rules` 和 `files`。规则包含非空 `version`、`approved_by`、`remove` 文本列表与 `retain` 文本列表；文件包含 `name` 和 PDF 字节的 `data` base64。禁止规范化重复规则与相互包含的删除/保留冲突；每个方向至少一条规则。`GET /api/demo` 返回四份运行时构造的中文演示 PDF 请求；`GET /api/health` 返回服务状态。

响应采用 `schema_version: 1.0`，包含规则、规范化规则 JSON 的 SHA256 `rule_hash`、文件最终字节 `sha256`、页数、发现项、覆盖范围与批次汇总。发现项以从零开始的 `rule_index` 关联规则，避免重复回显敏感值。报告内的规则仍属于敏感资料，应由用户按本地政策保管。

| 状态 | 含义 |
|---|---|
| `issues` | 存在明确删除规则匹配，或可检页面未找到应保留内容 |
| `review` | 可检查部分未发现明确问题，但仍需人工复核 |
| `error` | 文件无效、加密、超限或解析失败，可修复后重新检查 |
| `checked` | 协议预留，本版不产生此状态，不表示安全认证 |

坏 PDF 或非法 base64 只影响该文件，同批其余文件继续检查。规则错误、文件名重复与批次总量错误返回 HTTP 400，应修订整个请求后重试。

## 检查边界与资源

逐页检索 PyMuPDF 可抽取文字，使用 NFKC、大小写统一与字间空白去除匹配中文、全半角及换行文本。删除规则补充检索元数据、批注、附件可读内容、原对象字符串及可读流；保留规则只在页面检索。扫描或图像存在时，保留未匹配仅作为待人工确认，避免把缺少 OCR 当成确定过删。

所有正常结果均列明未运行 OCR、视觉遮盖判断、旧修订穷尽检查、复杂对象编码与规则批准真实性验证。隐藏文本中能够抽取的部分可检测，无法抽取的部分不保证覆盖。附件内容的简单文本解码不等同于检查嵌套 PDF、压缩包或任意二进制。不得将此报告作为安全、法律或披露批准认证。

每批 20 个文件，每文件 10 MB、200 页；合计 25 MB、500 页。规则每方向最多 100 条，每条 300 字。HTTP 请求上限 36 MB。每文件解析在独立子进程中进行，限 20 秒实际时间、15 秒 CPU、768 MB 地址空间；文本对象累计限 32 MB、单流 4 MB，最多 20,000 对象及 400 发现项。超限时给出人工覆盖提示或单文件错误，不宣称通过。服务串行执行检查，不适合面向互联网或多人并发。

PyMuPDF 固定版本为 `1.28.2`。本地开发使用既有依赖，未分发第三方源码；PyMuPDF 的 AGPL / 商业许可仍适用，商业分发应先独立审查许可。
