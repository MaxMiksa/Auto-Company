# 披露双检：界面与交互记录

本地浏览器工作台面向披露发布和质检人员，完整流程为建立批次、应用批准规则、上传 PDF、执行双向检查、逐项人工复核、导出交接记录。

| 设计选择 | 实际行为 |
| --- | --- |
| 档案审校视觉 | 暖纸色、深墨绿和朱红；衬线标题、批次索引与编号强调正式交接，不使用营销卡片 |
| 双向规则 | 删除与保留规则各至少一项，每行一条；版本、批准人必填；拒绝重复项及两组之间相同或包含的矛盾 |
| 批次输入 | 多选或拖入 PDF，可移除文件；最多 20 份，每份 10 MB，总计 25 MB；任何规则、文件或批次名称变更立即使原报告失效 |
| 检查结果 | 每份文件展示状态、页数、SHA-256、问题定位、检查覆盖和人工边界；原文件用临时本地对象 URL 预览，浏览器不支持时提供下载 |
| 人工复核 | 每项选择待复核、已确认或需返工，备注必填；覆盖确认明确不构成安全认证 |
| 交接门槛 | severity=error 的明确漏删、过删、脱敏错误及文件处理错误必须修复 PDF 并重新检查，人工确认不能绕过；扫描件保留待核属于 warning，需要实际视觉核对；其余项目全部实际确认并填写备注后才显示可交接 |
| 规则复用与导出 | 支持批准规则 JSON 导入／导出；完整报告导出 JSON 与可打印 HTML，包含实际复核记录及边界声明 |
| 恢复与隐私 | 只有用户勾选后，规则和报告才保存于当前标签页 sessionStorage；PDF 不持久化，关闭标签页清除；取消勾选立即清除保存记录 |
| 可恢复失败 | 网络故障、超时、无效 JSON 和文件错误有中文提示；保留当前输入以便修复重试，处理期间锁定输入 |
| 安全与可访问性 | 输入使用 textContent，HTML 导出统一转义；控件有标签、键盘焦点、状态 aria-live、窄屏重新编排及减少动画偏好；人工复核保留实际更新时间 |

演示由 GET `/api/demo` 返回四份中文构造 PDF，随后经过与普通文件一致的真实检查流程。演示不代表真实使用者、交易或安全认证。产品标识和 favicon 引用程序生成的 `/auto-company-icon.svg`；源设计为产品根目录 `icon.svg`。仓库缺少 `docs/product-logo-prompt.md`，按任务给定简洁几何档案图形设计，未改动程序生成图标。

检查 API 使用 POST `/api/check`，提交批次名称、批准规则及 PDF 的 base64 字节。所有处理在本机服务完成，没有外部资源、账号或远程请求。UI 的“可交接”仅表示本工具检查和人工复核流程完成，不能推导文件绝对安全。
