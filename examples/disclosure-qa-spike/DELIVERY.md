# 披露双检 · 本地交接

本产品供披露文件发布人员和质检人员检查最终 PDF 批次：明确必须删除的词和必须保留的事实，检查最终文件，处理发现与未覆盖项，并导出绑定文件摘要、批准规则和人工复核的交接记录。它不修改 PDF，不自动判断哪些真实资料应公开，不提供安全或法律合规认证。

## 安装和打开

需要 Ubuntu/WSL2 与 Python 3.12 或更新版本；文件检查使用 Linux 进程资源限制。浏览器可在 Windows 宿主运行。本地使用无需账户、云服务或网络上传，首次安装依赖需要网络。进入本产品目录：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --port 8765
```

在本机浏览器打开 `http://127.0.0.1:8765`。WSL2 下可使用 Windows 浏览器访问该地址。保持启动终端打开，结束时按 Ctrl+C。端口被占用时换用 `--port 8766`。服务仅监听回环地址，不应通过代理暴露到公网。

## 完整操作

1. 登记批次名称、规则版本和批准人。批准人字段是操作者的记录，不是签名认证；必须在组织自身流程中获得真实批准。
2. 添加最终 PDF，输入每行一个必须删除的词和必须保留的事实。当前同一清单适用于批次每份文件；不同要求请拆成不同批次。只支持明确文字约束，不推断语义、表格关系或身份类别。避免用过短、模糊或互相包含的规则。
3. 执行双向检查。逐文件查看删除匹配、保留事实缺失、页码或载体位置、未覆盖内容和 SHA256。删除命中和保留缺失需要回到原编辑工具修复 PDF，再替换文件重新检查。
4. 对每项待复核内容记录判断和非空备注。图像、附件、历史修订等仍需独立工具和人工复核；复核不能消除实际检查发现，也不能把结果转成安全认证。原文件可以在浏览器预览，浏览器不支持时下载到本地可信 PDF 查看器打开。
5. 导出 JSON 留存完整结构，导出 HTML 用浏览器打印或存为 PDF，随最终文件一起交接。报告包含规则和文件名，按文件保密等级管理。导出规则 JSON 可供下个批次导入并再次确认批准版本。更改规则或文件后旧结果失效，必须重检。

“加载构造样本”提供正确文字层、未真正删除、过度删除和扫描页四种合成材料，供学习使用；它不是客户数据、真人体验或准确率测量。

## 边界和恢复

| 场景 | 结果与处理 |
|---|---|
| 非 PDF、损坏、加密或无法解析 | 单文件错误，不阻断其他文件；在可信 PDF 工具解密/重新导出后替换重检 |
| 纯扫描、图片、图中文字 | 列为未覆盖/待复核；本产品没有 OCR，不保证图像里的删除或保留内容 |
| 抽取乱码、复杂字体、表格 | 文本存在不代表布局或可访问性完整；按最终页面逐项人工对照，必要时拆分规则或修复源文件 |
| 元数据、批注、附件、隐藏对象 | 检查支持的可提取文字，并明确范围；二进制附件、编码及加密载体不能用无匹配推断安全 |
| 旧修订、孤立对象、压缩及特殊 PDF 结构 | 仅做有限探测，必须独立检查，不宣称穷尽恢复或安全删除 |
| 规则冲突、空版本或空批准人 | 明确拒绝；修正输入后重试 |
| 文件或请求超限 | 最多 20 文件，每份 10 MiB，总共 25 MiB；每份最多 200 页、批次最多 500 页，拆批后重试 |
| 浏览器刷新/退出 | 默认不持久保存输入；按界面明确选择的本地留存选项操作。恢复的报告不包含 PDF 字节，重检需重新选择最终文件 |
| 导出后又修改 PDF | SHA256 已变化；旧报告只对应旧文件，必须重新检查并导出新报告 |

匹配做中文及全角字符规范化，并处理部分空白差异；这不能覆盖拼写变体、字形攻击、图像文字和业务语义。规则准备、批准和版本维护仍需要实际人员。没有证明相对完整人工工作流更省工或存在付费优势。

## 数据和许可

PDF 只发给本机服务，在内存中检查，不上传外部服务，服务不写原文件。原文件预览和导出使用浏览器本地对象；不要在公共机器留存报告，停止服务并清除主动保存的浏览器记录。合成样本和测试不会改写历史实验目录。

运行依赖 PyMuPDF，采用其既有许可条款（AGPL/商业许可路线），本次不购买许可、不进行商业分发。对外再分发或商用前应由负责人员按实际使用方式确认许可义务。Playwright 仅用于开发检查，无需安装即可使用产品。
