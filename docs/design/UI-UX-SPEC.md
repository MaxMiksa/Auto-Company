# Auto Company 界面与交互规范

本规范以 D 精修版为基准，规定管理中心、产品工作记录及后续新增界面的信息、视觉和交互标准；shadcn 迁移与日常增改均按此执行。

版本：1.6 · 更新日期：2026-10-03 · 适用：面向用户的 Web Dashboard。

## 1. 任务、信息与产品语义

### 1.1 主要用户任务

| 用户问题 | 首选位置 | 完成任务的动作 |
|---|---|---|
| 哪些产品最近发生变化，需要我处理什么？ | 管理中心产品行、状态过滤 | 搜索或筛选，进入产品 |
| 工作是否在运行，为什么还没开始？ | 产品运行状态、工作队列、并发摘要 | 查看位置和限制；使用现有合法控制 |
| 这一轮做了什么，有什么证据？ | 连续轮次时间轴 | 阅读报告、展开记录、查看本轮日志 |
| 产品是什么，已有何种可用成果？ | 产品详情右栏 | 查看真实截图、打开成果文档 |
| 我要建立或接入工作，如何配置？ | 新建工作、接入已有产品、设置 | 填写、检查摘要、明确提交方式 |
| 运行出错或数据不确定，如何判断？ | 就地异常说明与诊断 | 看时间、来源和具体错误，再选择已有恢复动作 |

首屏优先提供可识别的产品、当前运行语义、最新工作的事实与入口。高级配置、内部路径、命令、退出码、来源记录属于诊断或设置，不能挤占主报告。不要增加缺乏真实依据的经营指标、收益、完成率或账号信息。

### 1.2 信息层级与导航

- 一级导航：品牌入口、设置、当前本机或真实账号入口；移除重复的“产品中心”按钮。桌面详情顶栏同时容纳返回产品与工作记录/用量/日志，小屏自动换行。沿用已确认名称与标识，不在前端增改中决定新名称或 Logo。
- 管理中心：搜索与过滤 → 新建/接入 → 近期产品/其他产品 → 右侧工作队列及并发摘要。
- 产品详情：返回产品 → 工作记录/用量/日志 → 主栏连续轮次 → 右栏产品事实、成果、运行信息、诊断。
- 产品名称、短说明、最近运行时间主要归右栏；主栏标题描述该轮工作，不再重复一套产品概览。
- “工作记录”“用量”“日志”是同一产品的不同视图。切换保留产品身份；返回中心保留搜索、筛选与滚动位置。
- 不恢复已移除的 Next Action 界面。内部交接信息仍由现有机制保留，不借此删除数据。
- 新页面先说明它服务哪项用户任务、入口在哪里、返回哪里，再选布局。已有层级能容纳时不新增一级导航。

### 1.3 不可混淆的状态

| 对象 | 表达的事实 | 禁止推断 |
|---|---|---|
| 产品运行状态 | 正在运行、排队、暂停、空闲、需要处理、失败或状态待确认 | 最新一轮完成，所以产品已经交付或当前空闲 |
| 轮次状态 | 一次工作尝试的待开始、运行、完成、中断、失败等结果 | 完成若干轮，就自然进入交付或盈利阶段 |
| 检查结果 | 有证据的通过、失败、跳过数量及其时效 | 未登记检查等于全部通过；跳过等于通过 |
| 产品成果 | 实际存在且可访问的文档、截图或产物 | 有截图等于验收通过；链接存在等于成果仍有效 |
| 并发占用 | 当前有效运行证明对应的占用，及来源的新鲜度 | 未读到运行证据就计作零；暂停一定已释放占用 |
| 用量与成本 | 记录来源、统计范围、单位和可确认的数值 | 共享账号配额变化就是该项目精确消耗或费用 |

探索与产品开发在同一连续编号时间轴中呈现，探索默认可见。重启、切换模型、日志轮换不得重置展示编号。旧记录缺少连续身份时保留原始身份及来源，不能为追求整齐重新编号或制造缺失轮次。详细语义见[连续轮次说明](../product-cycles.md)。

“需要处理”必须有真实的未解决事项或治理阻断；保持原有 P1、Human Overrides 和归属验证。前端不得把“继续”变为绕过治理的快捷入口。

主列表不再提供“状态说明”展开模块或“新建工作限制”图标。权限与内部观测术语不进入主状态；新建不可用时直接显示简短原因。原始账本保留：核实进程停止后，未完成的启动尝试显示“已中断”，没有轮次显示“尚无轮次”；进程停止不等于产品交付。

## 2. 布局与响应式

### 2.1 度量原则

全部尺寸单位为 CSS px，字体以默认根字号 16px 下的像素值说明；用户缩放及字体设置应能正常放大。尺寸通常是最小值，内容增长时优先增高或换行，不能裁掉关键文本。只有缩略图、图标和明确规定的控件视觉尺寸采用固定值。

管理中心与工作记录页共用一个接近视口的白色页面外框，四周仅留窄边距；外部浅灰底、细边框及轻阴影将整页与窗口区分。框内仍以白底、细分隔线和清晰行列为主。报告可用浅底形成一个阅读区，队列单项可用轻边框。不要把每条事实、每段报告、每项检查都放进独立卡片；不要把所有状态变成胶囊。

### 2.2 全局尺寸

| 项目 | 标准值 | 使用说明 |
|---|---:|---|
| 页面外框距视口 | 桌面12；≤640为6 | 上下左右一致；页面随内容自然增长，底部仍保留同等外距 |
| 页面外框圆角/边线 | 8 / 1 | 白色页面、浅灰外底；阴影见3.3 |
| 页面内容最大宽度 | 1440 | 超宽屏居中，保留两侧空白，不无限拉长阅读行 |
| 框内内容左右边距 | 18 | 从白色页面边界计算；320–359视口宽度改为12，保证内容可用 |
| 顶栏 | 最小42高 | 桌面紧凑基线；触屏主交互目标需要44，触屏顶栏增至48 |
| 顶栏品牌字号/标识 | 14 / 17×17 | 小屏品牌12；保留原标识，不以头像替代品牌 |
| 品牌到主导航间距 | 32 | ≤760时18；不足时先收起账号文字，不藏“产品/设置” |
| 一级导航间距 | 30 | 文字左右留7，选中项底线3高 |
| 管理中心工具栏 | 最小80高 | 上12、下10；换行后自然增高，不能压缩为固定80 |
| 工具栏与列表间距 | 12 | 分隔线后到分组标题 |
| 详情二级导航 | 最小44高 | 返回入口与视图标签同一行，触屏项44高 |
| 二级导航到内容 | 16 | 不增加大型页面横幅 |
| 中心主栏/队列间距 | 16 | 队列左边线1，内部左边距15 |
| 时间轴主栏/右栏间距 | 14 | 沿用精修构图，不擅自改成等宽双栏 |
| 页面底部留白 | 24 | 避免最后一条记录贴底 |

外框只包裹页面导航与主体。跳转主内容入口、弹窗、抽屉、遮罩与通知保留在其外部；不得使用变换、滤镜或裁切使固定浮层相对外框定位或被圆角裁掉。外框借鉴 [shadcn SidebarInset 的内容容器组织](https://ui.shadcn.com/docs/components/radix/sidebar)，不因此新增侧边导航、固定画布或逐区块卡片。

### 2.3 断点矩阵

断点由内容空间决定，组件可以有自己的折叠点。不得仅用设备名称判断布局。

| 可用视口宽度 | 管理中心 | 产品详情 | 表单/导航 |
|---|---|---|---|
| ≥1450 | 主栏弹性；队列260 | 主栏弹性；右栏300 | 保持内容最大1440；不要同比放大字号 |
| 1001–1449 | 主栏弹性；队列214 | 主栏弹性；右栏268 | 桌面工具栏；紧凑行列 |
| 761–1000 | 队列下移，队列项目两列；工具栏两行 | 右栏245，主栏收窄；历史时间换到标题下 | 批量弹窗侧栏180，部分表单标签改上置 |
| 641–760 | 中心保持表格，队列在下方 | 时间轴单栏；产品事实区移到时间轴之后 | 详情导航间距12、标签间距8；提供“产品信息”页内跳转 |
| 360–640 | 产品行改纵向，队列单列；搜索独占一行 | 单栏时间轴；右栏改普通下方区块 | 过滤可横向滚动；主操作并列或自然换行；弹窗采用小屏布局 |
| 320–359 | 页边距12；其余同手机 | 编号/状态轨道保留，正文自然换行 | 两个主操作可上下排列；不缩字解决拥挤 |

批量新建弹窗另有 ≤650 的布局断点，见5.3。不得为了统一断点数字而改变既有使用效果。

移动端顺序：产品身份 → 最近工作 → 运行状态与最新轮次 → 更新时间与操作。无需横向滚动整个页面；日志、代码、确实需要双向阅读的表格可以在自身区域滚动，并提供可见边界。表头包含排序或筛选时，保留为可局部横滚的紧凑控件行，不能因手机重排而隐藏这些功能；产品行仍有字段标签。时间轴下方的产品信息可通过页内链接到达，不新增默认弹出的抽屉。

200%缩放时按可用宽度自然进入窄屏布局。320px宽度不得出现页面级横向滚动、被遮住的操作或无法关闭的弹窗。

### 2.4 间距尺度

| 尺度 | 使用场景 |
|---:|---|
| 2 | 紧邻的标题与说明、行内细微校正；不可作为按钮间隔 |
| 4 | 状态文字内部、紧凑记录两行之间 |
| 8 | 图标与文字、字段标签与输入框、相关操作间隔 |
| 12 | 产品缩略图与名称、紧凑区块内边距、列表分组间隔 |
| 16 | 常规组件间隔、表单字段间距、侧栏左右内边距 |
| 20 | 相邻表单组间距、紧凑弹窗分组 |
| 24 | 页面大分组间距、弹窗顶部/底部常规内边距 |
| 28 | 批量新建弹窗主区内边距；与既有B布局一致 |
| 32 | 不同任务区之间的显著间隔、桌面品牌到导航 |
| 40/48 | 大空状态上下留白；不用在密集列表中反复插入 |

4px是常规布局单位，2px为微调单位。18px页边距、14px列间距、30px状态圆、42px顶栏、51px历史行、66px产品行均是有用途的基线例外；不得据此新增任意零散值。新增组件选最近的既有尺度，确需例外时在组件规格中写明用途。

## 3. 视觉参数

### 3.1 字体与排版

中文界面确定使用思源黑体（Noto Sans SC），回退 Microsoft YaHei → PingFang SC → Arial → 系统无衬线。不默认引入远程字体，不使用浏览器合成的斜体传达状态。日志和命令使用 Cascadia Code → Consolas → 等宽字体。

| 用途 | 字号 / 行高 | 字重 | 规则 |
|---|---|---:|---|
| 常规页面标题、弹窗标题 | 20 / 26 | 700 | 页面没有标题区时不为满足规范额外添加大标题 |
| 详情右栏产品名 | 21 / 28 | 700 | D基线专用；允许完整换行 |
| 当前轮次标题 | 18 / 26 | 700 | ≤760为17 / 25；完整换行 |
| 产品名、历史轮次标题、中心分组标题 | 16 / 22 | 700 | 分组行高27；手机历史标题14 / 21 |
| 右栏分组标题 | 14 / 21 | 700 | 成果、运行信息、诊断 |
| 正文、表单、产品短说明 | 13 / 21 | 400 | 报告紧凑区域13 / 20；长文允许14 / 23 |
| 最新工作、记录事件名 | 13 / 21 | 400或700 | 最新工作400；记录事件名700；运行状态600 |
| 日期、表头、过滤、辅助信息 | 12 / 20 | 400 | 表头及选中项600或700；不使用更小字号承载重要事实 |
| 轮次大编号 | 当前23 / 28，历史20 / 23 | 700 | 使用等宽数字；编号旁不再重复“CYCLE”字样 |
| 日志正文 | 12 / 19 | 400 | 支持浏览器缩放，不让字号跟屏幕变小 |

字重只用400、600、700；禁止以650、730、780等任意数值模拟层级。中文常规字距0；英文字母不全大写拉宽，品牌已有字样除外。日期、计数、耗时、用量采用等宽数字以利对齐。

截断规则：产品名称在中心单行省略，详情完整换行；中心短说明单行省略；最近工作最多两行；成果链接可单行省略，但鼠标与键盘均能获得全名，手机有可访问的全文入口。报告、错误、危险操作后果、表单验证消息、状态待确认原因不得截断。长链接、连续英文与路径在所属区域内换行，不撑破页面。

截断内容的完整文本应存在于可访问名称或可操作详情中，不能只依赖鼠标悬停。英语按钮先增宽或换行，不为保持中文宽度缩小字号。

### 3.2 配色与对比

以下命名为设计角色，实施时映射到统一主题变量。颜色表是浅色模式标准；本次不自动新增深色模式。未来深色模式必须单独验证全部语义及对比。

| 角色 | 色值 | 用途 |
|---|---|---|
| 主文字 | #102659 | 标题、产品名、关键事实；对白约14.55:1 |
| 次文字 | #5D7092 | 日期、说明、字段标签；对白约5.00:1，报告浅底约4.66:1 |
| 主按钮/选中深蓝 | #112C68 | 主动作、过滤选中、当前完成轮次圆；白字 |
| 主按钮悬停 | #10265C | 不通过放大或投影模拟可点击 |
| 链接/焦点/运行强调 | #1257C4 | 链接、明确焦点、正在运行文字；对白约6.59:1 |
| 成功文字 | #146D39 | 真实通过与完成说明；对白约6.41:1 |
| 成功图形 | #179B52 | 已完成小圆/检查圆；白色对号保留清晰描边 |
| 注意文字 | #986300 | 需要处理、有限制的排队、过期证据；对白约5.10:1 |
| 危险/失败文字 | #A52828 | 失败、删除、破坏性后果；对白约7.16:1 |
| 页面/浮层 | #FFFFFF | 主背景 |
| 页面外底 | #F4F5F7 | 仅窄外边距可见的窗口背景 |
| 顶栏 | #FFFFFF | 与整张白页一致；层级由导航与分隔线表达 |
| 报告阅读底 | #F7F7F5 | 一轮报告整体区域 |
| 输入浅底 | #F8F9FC | 搜索或只读字段区域 |
| 悬停/选中浅底 | #F3F6FC | 行悬停、菜单焦点、轻选择背景 |
| 装饰分隔线 | #E3E7ED | 行列分隔；不作为唯一控件轮廓 |
| 控件边界 | #7C8CA7 | 输入、未填充按钮等需要独立识别的边界；对白约3.41:1，报告浅底约3.17:1 |
| 时间轴轨道 | #607DA8 | 1px连续线；重要状态由节点与文字表达 |
| 错误浅底 | #FFF5F5 | 局部错误区域，搭配危险文字 |

对比值为纯色对纯白的计算值，非全页面可访问性认证。组合在浅底、半透明层或禁用态时应重新验证。原基线的 #6B7DA1 浅蓝文字对白约4.14:1，不能继续用于12–13px正常正文；深一档的次文字是本规范明确要求的修正。

正文最少4.5:1，大字最少3:1；需要识别的控件边界、状态图形与焦点最少3:1。装饰分隔线可低于此值，但不能承担唯一识别作用。所有状态同时有文字或可访问名称，不仅靠颜色区分。对比要求参考 [W3C文本对比说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

### 3.3 形状、边框与层级

| 元素 | 圆角 | 边框/阴影 |
|---|---:|---|
| 整页外框 | 8 | 1px #E3E7ED；0 2px 10px 深蓝5%阴影 |
| 列表、表格、侧栏分区 | 0 | 行间1px分隔，无阴影 |
| 截图缩略图 | 2 | 1px边框；不加厚外框 |
| 按钮、输入框 | shadcn默认 | 控件源码决定圆角、边线、阴影与交互；集中应用品牌色和字体 |
| 报告浅底 | 4 | 报告无边框 |
| 队列项目 | 5 | 1px轻边框，无阴影 |
| 菜单、弹出层 | 6 | 1px边界；0 8px 24px 深蓝12%阴影 |
| 弹窗 | 8 | 1px边界；0 20px 60px 深蓝18%阴影 |
| 头像、状态圆、时间节点 | 50% | 仅这些元素使用完整圆形 |

整页外框可以使用上述轻阴影；框内不使用大面积渐变、玻璃背景、逐项浮起卡片、装饰色块或表情图标。品牌保留已有图形，操作与状态图标统一采用官方图标库。不要通过连续加深阴影表现普通层级。

层级顺序：页面内容0 → 行菜单20 → 粘性局部导航30（仅确有需求时）→ 遮罩100 → 抽屉/弹窗110 → 浮层内菜单120 → 提示130。层级解决实际遮挡，不允许不断增大数值掩盖布局错误。顶栏默认随页面滚动；不可用未请求的固定顶栏占据小屏阅读区。

### 3.4 图标与状态

操作与状态图标统一使用 [Lucide 官方 SVG 图标库](https://lucide.dev/guide/)，保留官方路径、端点和几何，不再用文字字符、CSS伪元素或手绘路径仿制同一图标。通用视觉尺寸16或18；单独按钮内可20。线宽1.5–2，整套一致。外链图标12，作为文字补充；现有品牌标识不受此限制。状态图标大尺寸30，最新一轮18，检查结果23。图标视觉尺寸与可点击区域分开。

每个状态只由一个SVG绘制。迁移时删除旧状态的伪元素、扇区背景和重复圆边，避免一个状态出现两套轮廓。账号菜单的 ChevronDown 使用真实SVG，14×14，与头像、文字垂直居中，不使用文本箭头及基线偏移补偿。

| 语义 | 图形 | 文案及约束 |
|---|---|---|
| 待开始/排队/空闲 | Clock | 必须用文字区分三者；不能只显示同一时钟 |
| 正在运行 | CirclePlay | 静态业务执行状态；无百分比、无逐渐填满、无剩余时间推断 |
| 已完成轮次 | CircleCheckBig | 时间轴最新轮可用深蓝实底，其余深蓝；中心最新轮可用绿色 |
| 已暂停 | CirclePause | 不用停止方块或失败叉号替代 |
| 来源访问权限 | 不占用运行状态列 | 放在来源管理中；主列表显示核实后的运行状态 |
| 需要处理 | CircleAlert | 注意色；同时提供具体事项入口 |
| 失败 | CircleX | 危险色，保留失败原因入口 |
| 中断/超时 | 对应非完成状态及明确文字 | 不使用对号；超时不暗示仍运行；是否可重试由后端语义决定 |
| 状态读取失败 | CircleAlert | 仅在真实读取故障时出现，提供刷新；正常列表必须完成进程观测，不以权限说明替代 |

图标旁已有完整文字时，图标对屏幕阅读器隐藏；只有图标的操作必须有“查看本轮日志”“更多操作”等具体名称。业务运行使用静态 CirclePlay，网络读取等待才使用 LoaderCircle，并分别配“正在运行”和“正在读取”等实际文字；不能仅凭动画就推定后台工作已开始。

## 4. 页面组件

### 4.1 管理中心工具栏

搜索视觉宽度208、最低125、高35；≤640全宽。过滤项高34、左右内边距11、间隔5、圆角4。搜索、过滤与主动作触屏时有效高度增至44；不以重叠的不可见区域扩展触控范围。

过滤依次为“全部、正在工作、已排队、需要处理、归档”，数字来自相同口径的真实数据。选中项深蓝底白字，其余浅底深字。没有数字的按钮按文字整体居中，不保留空计数、假间距或无意义的对齐占位。只有真正相互排斥的过滤使用单选交互；查询条件不假装成页面导航标签。

右侧“新建工作”为唯一填充主按钮，“接入已有产品”为描边次按钮；按钮高34、左右内边距18、间隔10。并发摘要位于工作队列内，运行中、等待中和并发上限分三行，数值使用统一徽标。状态表达必须能区分已确认占用、等待数和证据待确认；数据不可确认时不能默默显示0。

搜索在输入后短暂稳定再更新或即时本地过滤；不得每次输入夺走焦点。清空搜索可键盘执行。加载/刷新保持原列表位置；筛选结果变化可用简短辅助提示播报，不逐项朗读整页。

默认按真实更新时间降序，近期组显示前4项，其余归其他产品。其他产品默认显示其中最新4项，使用标准Collapsible展开全部/收起；刷新保留展开选择。两组标题计数来自当下集合；少于4项不补位，不为了参考图数量造数据。归档与特定状态筛选的分组遵循真实集合，组为空时不保留空壳标题。

| 列 | 桌面宽度规则 | 内容 |
|---|---|---|
| 产品 | 剩余宽度的2.45份 | 92×55截图、间距12、产品名与短说明 |
| 最近工作 | 1.68份 | 两行以内的真实工作标题；缺失时“暂无工作记录” |

产品名称是主要跳转链接，真实截图可链接到同一产品；整行可提供可预测的点击行为，但不得把菜单按钮包进链接，或让复制文本触发导航。行悬停使用浅底，键盘焦点同样可见。更多操作桌面可在悬停/焦点出现，触屏始终可见；不能盖住时间文字，必须预留空间。

### 4.3 工作队列

桌面队列右侧栏宽214/260，标题16/27，条目间距8。每条采用24px序号列、弹性内容列、32px操作区；列间距8，内边距10。序号视觉块24×28，产品名13/20加粗；方向和时间12/18。基线中15px的更多菜单视觉可保留，但按钮区域必须扩大至桌面至少32×32。

队列序号表示当前排队位置，不是优先级评分或固定开工时间。只展示真实等待项；无项目显示“目前没有等待中的工作”。等待原因来自实际容量或约束，不捏造倒计时。队列与中心相同产品使用同一身份链接。

队列变化不自动把用户滚到顶部，不关闭已展开菜单，不让键盘焦点丢失。若条目在操作中消失，说明结果，并把焦点移到下一条同位置操作或队列标题。

排序若现有能力支持，应同时提供按钮方式，不能只有拖拽。仅改变显示顺序不得偷偷改变调度优先级。取消排队必须准确说明取消的是等待项还是运行任务，不能混用“停止”。

| 宽度 | 编号列 | 状态节点 | 两侧列间距 | 正文起点（相对主栏左侧） |

| ≥1001 | 54 | 30 | 18 | 120 |
| 761–1000 | 42 | 28 | 12 | 94 |

当前轮次默认展开；历史最小51高，标题16/22，日期时间12/20，展开箭头12。当前标题18/26，标题右侧放真实更新时间及可用的本轮日志入口；窄屏允许时间移到次行。报告阶段放在标题附近，例如“提交验收”，这是报告自述阶段，不替代真实运行状态。

历史展开不改变轮次排序，不加载伪造的占位记录。多个轮次可同时展开；展开项具有明确名称与展开状态。展开按钮和日志链接分别可操作，不出现一次点击同时展开及跳转。使用页面内锚点时，刷新和返回后尽量保留当前记录位置。

### 4.5 报告与轮内微时间轴

报告浅底区域上间距6，内边距上9、左右12、下10，圆角4。区域内顺序：最新工作汇报 → 本轮记录 → 检查摘要与本轮日志。上方标题已给时间时，报告内部不再次可见重复同一时间。

报告正文13/20，完整表达工作结果与限制。长报告可以提供“展开完整报告”，但折叠时保留结论、主要失败和限制，不按固定字符数截断到歧义。正文最大舒适阅读宽度约80个英文字符或40个汉字；宽屏可限制正文而不强制给两侧加卡片。

微时间轴距报告段落9，顶部分隔线1，内边距上7，列表距标题5。桌面时间列52、列间距28，节点6×6，轨道1；节点中心在时间列右侧12，正文从80开始。事件名预留90，详情与事件间距16。移动端时间列35、间距18、正文起点53，事件名与说明上下排列。

每条记录保留真实时间、简明事件名和有用结果。时间相同、日期跨天或来源时间不一致时应呈现实际值，必要时显示日期；不能为视觉顺序改写时间。命令、绝对路径、退出码和重复报告链接转到诊断，不让工作记录变为技术清单。

底行距记录10，左右分别为检查摘要与“查看本轮日志”，不足时换行。显示“通过8项，失败1项，跳过2项”时必须来自记录；失败及跳过不可隐藏在绿色总数后。没有检查记录显示“暂无已登记检查”；过期结果标明时间和“非本轮”或实际范围。没有日志时说明不可用，不提供死链接。

桌面宽268/300，平板245；内边距上12、左右16，轻边框1。下方分区以线和留白分隔，不能嵌套卡片。

固定内容顺序：产品名 → 短说明 → 当前运行状态 → 真实截图 → 项目成果 → 运行信息 → 折叠诊断。产品名完整换行，说明13/20。状态圆23，距文字9，状态区上6、下9。

成果采用两列文字链接，列间距12、行间距8，图标18，正文13/19。只有可用成果在主区展示；失效链接、找不到的文件和过期原因放诊断，并在确实影响用户判断时给出简短提示。成果数量少时自然留白，不补示例条目。

诊断默认折叠，标题14/21，可键盘展开。来源、路径、退出码、读取时间、截图详情和失效成果归此区。自动刷新设置、手动刷新和相关读取信息放设置中；不要再加一条重复页脚。诊断内正常可阅读文字至少12px。

### 4.7 用量与日志

用量先说明统计范围、时间段、来源更新时间，再呈现数值。未知使用“暂无可确认数据”，不写0；估算显式标“估算”，不能保留不合理精度。不同模型、引擎、货币、单位不直接相加。图表必须有单位、时间刻度、图例和文本或表格等价内容；不使用只有色块的饼图表达关键事实。

优先用紧凑表格比较轮次或时间段，只有趋势确实有解释价值时才加图表。禁止为迁移采用默认仪表盘模板而新增虚构收益、增长率或消耗预算的进度条。

日志保留原文、真实顺序和时间。正文12/19等宽，提供范围、查找、复制或下载的现有能力；复制必须告诉用户范围。自动追踪尾部只有在用户已经位于底部且启用跟随时进行；用户向上阅读后暂停跟随，显示“有新日志”入口。长行默认允许局部横向滚动，可提供换行切换；不让整页变宽。

连接断开时保留已载入日志，标明最后成功读取时间。重试不擦掉历史。不把错误日志涂成整屏高饱和红底，也不自动掩盖失败行。

## 5. 交互与状态

### 5.1 按钮、输入与选择

| 控件 | 桌面 | 触屏/小屏 | 行为 |
|---|---|---|---|
| 通用按钮 | Button默认36高；仅紧凑场景选官方sm | 最小44高 | 一个区域通常只有一个填充主动作；不按页面覆盖 |
| 输入/选择 | Input与NativeSelect默认36高 | 最小44高 | 沿用官方边线、内边距和焦点状态 |
| 图标按钮 | 官方icon或icon-sm变体 | 最小44×44 | 可访问名称不可缺失 |
| 复选框/单选框 | 图形16–18，整行可点 | 整行最小44高 | 文字标签与输入关联；状态不只靠颜色 |
| 多行输入 | Textarea默认最小高度与内边距 | 同左，可向下增长 | 可调整高度，不让输入覆盖提交区 |
| 菜单项 | DropdownMenu默认 | 最小44高 | 危险操作独立分隔，不默认聚焦 |

按钮正常、悬停、按下、聚焦、禁用、提交中六态均需覆盖。禁用沿用组件标准状态；若原因不明显，在旁边说明，不能让用户必须悬停禁用按钮才能知道原因。提交中按钮文字改为准确动作如“正在加入队列…”，避免宽度变化及重复提交；其余表单状态保留。

标签始终可见，提示文字不替代标签。可选项用“（可选）”，默认值的含义说清楚。错误出现在字段下方并关联字段；提交失败保留输入。错误必须描述可修正事项，如“项目数量须为1–100”，不得只写“参数错误”。实际边界以服务端契约为准，不由设计稿创造新限制。

短选项使用官方Native Select或Select，不能只给原生select加标记。长列表需要搜索时使用Command组合或Combobox。不为两个选项使用大型卡片选择器。不把运行状态或模型能力中不存在的选项加入表单。

### 5.2 焦点、键盘与触摸

- 通用组件保留官方focus-visible行为，通过共享ring变量应用品牌焦点色；原生内容链接保留可见轮廓，不以页面CSS抹去组件焦点。
- 页面提供“跳到主要内容”。Tab顺序与视觉阅读顺序一致；不用正数强行重排顺序。
- 链接Enter打开；按钮Enter/Space激活；标准菜单支持方向键、Home/End、Esc；单选与标签页使用标准键盘模式。
- 视图标签若切换无需等待可随焦点激活；存在网络等待则用Enter/Space确认，避免方向键不停发起加载。
- 所有任务都能只用键盘完成。鼠标悬停出现的信息要能通过焦点或明确操作获得，手机无需悬停。
- 自动刷新保留焦点所在的逻辑对象、展开状态和输入内容。对象确实被删除时，移到就近合理位置并说明结果。
- 桌面独立目标至少24×24，本产品常规图标按钮采用32×32；触屏采用44×44，相邻独立操作间隔至少8。点击区域不能互相覆盖。行内文字链接保留自然排版并加清晰下划线或可辨链接样式。

24px是WCAG最低目标尺寸的通用基准，本规范的32/44是产品设计要求；例外须依据实际场景，不可统一宣称小图标都豁免。[W3C目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

### 5.3 弹窗、抽屉与菜单

普通表单弹窗最大宽620，左右离屏至少16，最高视口减40；内边距24，字段组间距20，标题与说明间距8。短确认弹窗最大440。遮罩为深蓝35%透明，无模糊或仅轻微模糊；不能让背景仍可操作。

批量新建工作沿用B布局：弹窗最大1080宽、距屏至少24；高不超过720或动态视口减48。顶部24×28内边距，左侧工作组220宽，主区28内边距，底部20×28。761–1000宽度工作组栏180；≤650弹窗距屏8，工作组改横向列表，主体内边距20×16，底部14×16。手机主体表单按内容改单列；模型与强度仅在不压缩值时并排。

当视口高度≤520时，批量弹窗改为整体纵向滚动，仅标题和关闭入口固定顶部；配置组、数量、方向与提交区都按自然高度排列。不得让固定头尾把主体压成仅几像素的交叉区域；验收须实际读到字段、操作数量及方向，并滚动到提交。短屏队列抽屉同样保留固定关闭入口。

批量新建保留明确的工作组选择、模板、引擎/模型/推理强度、项目数量、可选方向与保存模板入口。底部展示真实提交数量和提交方式：“开始运行”与“仅加入队列”必须可区分；默认选择遵循现有产品设置，不因换组件而改变。并发不足、部分失败、已创建但未开始等结果必须逐项明确，不能把“已提交”写成“正在运行”。

抽屉用于队列详细操作或辅助配置，桌面最大460宽；小屏不超过视口宽度，高度适配动态视口。标题与关闭固定，主体独立滚动，底部操作在需要时固定；内容不被软键盘或底部安全区遮挡。不能为每个普通详情都新建抽屉。

菜单最小宽180、最大宽280，内边距4，距触发点4；靠近屏幕边缘时自动翻转或位移。更多菜单只收纳次要动作，常用主动作直接可见。菜单内没有适用动作时隐藏入口或清晰解释，不打开空菜单。

打开弹窗时焦点进入适当位置：普通短表单可首字段，长内容先标题或说明，破坏性确认先安全操作。Tab被限制在模态内部，Esc关闭，关闭后焦点回到触发元素；触发元素已消失时回到合理后继。所有弹窗有明确标题与关闭按钮。背景不可聚焦，也不能滚动穿透。保存中如不能立刻关闭，应说明当前状态且不要暗示关闭等于取消后端工作。[WAI模态交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

### 5.4 加载、空态、错误与过期

| 状态 | 呈现 | 恢复/下一步 |
|---|---|---|
| 首次加载 | 保留页面结构；超过约300ms才显示轻量占位 | 用“正在读取产品…”描述请求；无虚构行名、数字或状态 |
| 背景刷新 | 保留当前内容，不闪白、不重排焦点 | 局部更新，必要时显示正在更新；不每次刷新弹Toast |
| 首次无产品 | 一句说明、一个主动作“新建工作”、次入口“接入已有产品” | 不放演示产品冒充真实数据 |
| 搜索无结果 | 显示实际搜索条件，提供“清除筛选” | 不与尚未创建产品混同 |
| 无轮次/无报告/无检查 | 对应局部说明 | 保留已有其他信息；不展示完成对号 |
| 请求失败 | 就地说明失败范围及可执行重试 | 保留上次成功数据及其时间，不将旧数据画成实时 |
| 部分失败 | 成功项与失败项分别说明 | 重试仅覆盖可重试范围，不能重复创建已成功项 |
| 证据过期 | “状态待确认”，显示最近有效时间 | 保留上次状态作为历史说明，不继续计为确认运行或确认空闲 |
| 权限或治理阻断 | 具体原因和现有处理入口 | 不暗中尝试更高权限，不把停止保护当作普通失败重试 |

过期阈值、刷新周期、超时时间由已有数据契约决定，前端不得自创固定分钟数改变业务含义。给用户展示的Dashboard必须接入真实运行观测和可用执行环境；不得以只读预览代替。若连接状态严重影响操作，提示放在受影响区附近；禁止遮住主内容的永久大型红色横幅。

成功Toast只确认刚发生的用户动作，默认4秒；重要失败以持久内联信息为主，不能只留一个瞬时Toast。屏幕阅读器使用适当的状态播报，普通刷新不用高优先级警报。退出页面后仍可能进行的操作要说明持续性。

### 5.5 危险操作与运行控制

“暂停”“停止”“取消排队”“归档”“删除”分别表达真实操作，不能统一叫“关闭”。按钮出现与可用性遵循现有权限、归属、治理与后端状态；视觉迁移不改变这些规则。

普通可逆动作直接执行并提供结果；真实不可逆删除、覆盖或终止正在运行的工作，使用明确后果确认。确认内容包含对象、影响范围、是否可恢复，主按钮使用具体动词，不写“是”。默认焦点在取消或安全入口，不使用预勾选确认。已有授权/确认流程优先，不额外添加层层确认。

停止请求已接收时先显示“正在停止”或实际响应，不立刻把状态改成“已停止”。归档不暗示删除文件；删除历史展示不暗示清除了外部效果。只有后台确认后才呈现最终结果。

### 5.6 动效

颜色与透明度变化120ms；菜单出现120ms；折叠展开160ms；抽屉/弹窗160–200ms，缓出。位移动画最多8px，抽屉可沿边缘滑入；不使用弹跳、连续呼吸、强光扫动或放大卡片。

业务运行图标保持静态 CirclePlay，不添加旋转。网络读取可使用组件提供的 LoaderCircle 加载反馈，文字必须表达实际请求状态，不能用动画假装真实运行。用户开启减少动态效果时关闭非必要位移、旋转和骨架闪动，状态仍由文字与静态图标完整表达。自动新增记录不做强制滚动或整列动画。

## 6. 文案与语言

### 6.1 术语与语气

| 中文 | 英文 | 使用说明 |
|---|---|---|
| 产品 | Products / Product | 中心主对象，不随意替换成公司账号或工作区 |
| 工作记录 | Work journal | 用户可阅读的轮次报告与记录 |
| 轮次 | Cycle | 一次尝试；界面数字旁可省略术语 |
| 正在运行 | Running | 有有效运行证据 |
| 已排队 | Queued | 实际等待队列中的项 |
| 已暂停 | Paused | 真实暂停，不等于失败或已交付 |
| 已空闲 | Idle | 可确认的未运行状态 |
| 需要处理 | Needs attention | 有具体未解决事项 |
| 状态待确认 | Status unconfirmed | 无足够当前证据；保留原因与时间 |
| 已完成 | Completed | 只用于明确完成的对象，如轮次或检查 |
| 项目成果 | Artifacts | 可访问的真实产物 |
| 诊断 | Diagnostics | 技术细节与数据来源 |

动作使用具体动词：“新建工作”“加入队列”“查看本轮日志”“重试读取”。状态使用事实句，失败说明先说发生了什么，再给下一步。避免“AI正在努力”“即将完成”“完美交付”等无依据表达，不显示精确但未经确认的剩余时间。

没有真实账号时显示“本机”，不能复制概念图里的“张三”、头像或账号菜单。名称、方向和报告内容来自用户或真实记录，示例只存在于明确标注的演示或测试环境。

### 6.2 本地化与时间

全部固定界面文字、按钮、提示、空态、错误、可访问名称都走同一中英语言机制；不允许页面中文而弹窗/状态仍残留英文。产品名、用户输入、原始日志与历史报告按原记录保留，不假装已翻译。

显式语言偏好优先，未设置时按既有系统语言规则。产品历史语言锁定与新产品语言规则保持原样；切换UI语言不能重写账本内容。修改翻译时保留定制指令，并按仓库流程更新来源哈希。

日期在每次渲染时按浏览器本地日历判断：今天/昨天（英文 Today/Yesterday）；其余本年度 MM-DD，跨年 YYYY-MM-DD。时间 HH:mm，不显示秒。产品列表日期和时间同行；日期输入控件值保留完整 ISO 日期。用“最近运行”不代替“创建时间”；不能把读取时间写成运行结束时间。

数量、金额和时长使用本地化格式；0、未知、未记录、不可用四者区分。时长可“5分35秒”或“5m 35s”，缺结束证据时不能展示已完成耗时。英文扩展约30%的长度也要能换行；不能把固定宽度当成翻译长度限制。

## 7. shadcn 组件选型与治理

### 7.1 使用原则

通用控件优先使用shadcn官方组件并保留标准交互，以默认样式为基础，只集中调整品牌色、字体和必要尺寸。页面只选择共享变体，不再覆盖按钮高度、边框、圆角、阴影或选择箭头位置。组件源码放在项目内是官方分发方式；是否使用组件应看实际渲染与交互，不能只看运行依赖名称。布局、连续时间轴和业务内容遵守本规范，但不得为保留旧外观把组件改回旧控件。[shadcn文档](https://ui.shadcn.com/docs)

采用实际的基础组件及其标准交互后，再验收焦点、键盘、语义与视觉。只给旧按钮改名、套默认样式或画出类似外观，不能算完成迁移。迁移范围由当次任务决定，不因此引入额外页面、框架服务、账号系统或远程字体。

### 7.2 组件映射

| 界面需求 | shadcn基础组件 | Auto Company 定制要求 |
|---|---|---|
| 主次动作、文本动作、图标按钮 | Button | 使用官方default/outline/ghost/destructive及size变体；品牌色与触屏最小44集中定义 |
| 搜索、模型、方向等表单 | Input、Textarea、Label/Field | 固定可见标签、关联错误；不得复制大卡片表单模板 |
| 引擎/强度等选择 | Select或Native Select | 只显示真实支持值；长选项仍可读 |
| 搜索产品或长列表 | Combobox | 仅列表长度与任务需要时采用；可键盘搜索 |
| 提交方式与配置选择 | Radio Group、Checkbox、Switch | Radio为互斥选择，Switch只代表立即生效的开关，不替代提交选择 |
| 产品视图切换 | Tabs | 使用官方line变体；工作记录与配置组都由Tabs处理键盘 |

| 历史轮次与诊断 | Collapsible/Accordion | 连续轨道与业务状态由自有组件呈现；支持多个历史项同时展开 |
| 产品行与用量数据 | Table；复杂筛选排序可采用官方Data Table组合 | 当前单列排序与两类精确业务过滤保留现有数据规则；Table负责语义，手机重排，不把每一行变Card |
| 辅助说明 | Tooltip/Popover | 必须可聚焦/触摸访问，关键错误不藏在Tooltip |
| 结果通知 | Sonner | 确认动作，避免持续刷新通知；失败有持久Alert或字段错误 |
| 初始读取 | Skeleton | 只模拟结构；减少动态设置下不闪动 |

| 普通提示、错误 | Alert或字段内联错误 | 就近、紧凑、有真实原因；不是所有状态都用Alert |
| 真实账号/本机入口 | Avatar + Dropdown Menu | 没有账号不生成头像身份；本机保留现有设置入口 |

| 时间轴/微时间轴/状态图标/轮次摘要 | 自有业务组件 + Lucide官方SVG | 组合基础组件；固定状态语义，禁止用Progress充当运行状态 |

Card只用于需要整体边界的独立任务对象，不能成为页面默认容器。Badge只适用于必要的分类或短标签，如立项前探索；状态优先图标加普通文字。Progress仅能用于有可信分子和分母的真实进度，本产品运行轮次默认不具备这一条件。

### 7.3 以后增改的决策顺序

1. 明确用户任务、真实数据来源、操作后果及未知情况。
2. 决定在现有信息层级中的位置，说明默认可见与按需展开的内容。
3. 选择已有业务组件及基础组件，列出需要的状态与窄屏行为。
4. 通用控件采用官方默认值与共享主题；本规范布局参数只用于业务容器。确需尺寸调整集中定义，不按页面重做控件。
5. 对照真实记录验收，然后更新规范中真正发生变化的部分及任务证据。

新增一个颜色、字号、圆角、侧栏宽度或断点前，先检查已有角色能否表达。只出现一次的业务差异不应立刻形成全局组件；会重复的视觉/交互规则也不应散落成多套局部覆写。

用户最新明确决定优先于本规范；真实数据语义、可访问性和保护规则不得因参考图而失真。本规范未覆盖的小改动可由实施者按既有原则判断，不额外制造审批流程。若改变用户任务、导航层级、术语含义、默认运行方式或真实权限边界，应回到当次用户目标明确范围。

规范更新要写明改变了哪条规则及其理由，详细实拍、测试和决策证据放当次acceptance目录。本文件不变成逐次聊天记录。旧规范有价值的约束不得被静默删除；已失效截图注明为历史参考，不继续作为验收真值。

### 7.4 迁移不能改变的行为

- 真实记录、稳定产品身份、轮次连续编号、探索可见性、历史展开与原始来源。
- 既有表单默认值、模板、并发、排队和运行控制语义；实际数据验证与权限检查。
- 中英语言机制、用户定制指令、页面地址、深链接及可用的日志与成果入口。
- 自动刷新时的焦点、用户正在输入的内容、查看位置和已展开信息。
- 失败、未知、过期、跳过、治理阻断与部分成功状态，不能为缩短实现只保留“成功/失败”。

### 8.2 验收方式与证据

每次改动按实际风险验证涉及的组件与用户路径，不机械重跑全项目。改变共享主题、弹窗或布局时至少检查中心、时间轴、长表单三种典型画面；只改文案时检查布局与语言即可。真实模型运行、调度或生产部署不能为了截图顺便启动。

视觉对照使用浏览器真实截图，先修页面再重拍，不修改截图像素或数据。参考图中的示例产品、账号、时间和检查数不能作为验收内容。状态边界可用明确标记的测试数据验证，但其截图与结论不能当作真实运行证明。

验收记录写清实际环境、通过范围、失败及修复、未执行项。只测Windows/Chromium时不声称macOS、所有浏览器或全平台已通过。手工视觉判断与自动验证分别说明，不把“截图看起来相近”当成交互正确的证据。

### 8.3 控件迁移验收

- 实际渲染对应官方组件；静态原语可以通过React静态渲染输出完整结构，不能只套class或标记。
- 同类控件共享源码与变体；菜单定位、键盘选择、模态焦点与关闭交由组件。
- 删除被替代的交互、原生展开实现、Toast计时器与冲突样式。
- 保留自定义实现必须写明业务原因与边界；旧实现不是保留理由。

### 8.4 交付判断

交付必须同时满足信息真实、主要任务可完成、D视觉层级一致、关键状态可理解、键盘与窄屏可用。局部参考像素与可访问性发生冲突时，保留布局意图并修正可访问性，在任务证据中说明。任何未覆盖的行为或平台如实标注，不以本规范的存在替代验收。
